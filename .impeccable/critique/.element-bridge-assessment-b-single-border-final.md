## 命中归属与判读

- `line-length`：桌面浅色视图中定位到文档导语、Demo 功能说明、接入说明三个 `<p>` 段落，提示约 86 chars/line。它们是会自然折行的中文说明段落，并非表单控件标签或单行操作文案；规则对这类中文文档段落的判断不直接构成控件焦点缺陷。
- `layout-transition`（`width`）：定位到 demo 内 `.el-tabs__active-bar`，是 Element Plus 页签激活条的宽度过渡，与下拉焦点边框无关，属于对预期页签反馈的泛化命中。
- `buried-raster`：两处定位到 VitePress 代码片段的 `button.copy`，是默认隐藏、交互时显现的代码复制图标，不属于 lx-ui 控件。
- `bounce-easing` 与 `layout-transition`（`height, padding-top, padding-bottom`）：定位到文档页 `BODY` 根节点。该宽泛目标代表文档外壳运动规则，截图 banner 会覆盖一部分顶部导航；它不是 select wrapper 的焦点线。按本次控件边框目标，这两项属于外壳命中/范围误报。
- 375px `clipped-overflow-container`：定位到 VitePress 移动导航的 `span.container`，在将焦点控件滚入视口后，其矩形为 `[335, -278, 16, 14]`；属于屏外移动导航图标的预期裁切，不是表单容器横向溢出。
- 375px 浅色错误态 `low-contrast` 两条：实际命中两个 `.el-form-item__error` 提示文字（“请输入任务名称”“请选择责任部门”），检测到 `#c45656` 对白底约 `4.4:1`，低于 `4.5:1` AA 文本门槛。这是有效的邻近错误提示可读性问题，不是焦点边框命中；建议后续提高错误提示文字色对比度并复测。
- HUD 的 `ai-color-palette` 标记遍及主题 cyan/violet 文本，符合此 demo 的 HUD 主题意图；该规则不等价于对局部文字可读性的验证，错误态对比仍需单独检查。

## 焦点 computed style

普通状态通过 Tab 可聚焦的真实 wrapper 获得焦点；单选框错误由“校验表单”触发，确实处于 `.el-form-item.is-error`。demo 没有给多选协同部门配置校验规则，因此多选错误态通过浏览器临时给其父 `.el-form-item` 加 `is-error` 检查错误 CSS 分支，属于样式模拟而非业务校验结果。

过渡结束后，浅色普通焦点边框为 `rgb(0, 96, 169)`，HUD 普通焦点为 `rgb(56, 189, 248)`；浅色错误焦点为 `rgb(196, 86, 86)`，HUD 错误焦点为 `rgb(247, 137, 137)`。四种状态均为 `1px solid`、`4px` 圆角、`box-shadow: none`、`outline-style: none`、`outline-offset: 0px`。桌面 wrapper 尺寸为 `319×32px`，375px 视口为 `301×32px`；主题切换和错误状态均不改变控件宽高。错误底色在浅色主题为 `rgb(254, 240, 240)`，HUD 为 `rgba(245, 108, 108, 0.15)`。
