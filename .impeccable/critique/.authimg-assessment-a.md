# AuthImg 设计评估 A

> 评审方式：单上下文降级评估。`gpt-6-sol` 子 Agent 服务返回 HTTP 503；此评估在读取 detector 结果前完成。目标：Vue3 管理端 AuthImg，主要使用场景为 `/h5/carousel`。

## 设计特异性

管理端的深色导航栏、浅色工作区和蓝色主操作与现有 LinkX 后台一致。AuthImg 在轮播图表格中以 170x80 图片呈现，尺寸稳定且不会抢过标题与操作。组件自身采用常见加载/图片图标，作为内部工具能融入现有 Element Plus 外观，但缺少 LinkX 组件库已有的 `LxAuthImg`/`LxIcon` 品牌细节；整体是合格的后台通用组件，产品专属性中等。

本评估在本地 Mock `/h5/carousel` 桌面视图观察了已加载图片状态。失败占位和减少动效由定向浏览器用例验证；当前浏览器桥接不提供 DOM 修改或路由拦截，因此没有声称人工观察到失败态截图。

## 认知负荷

- 单一焦点：通过，图片状态不干扰表格主任务。
- 分组：通过，资源位于轮播图列。
- 视觉层级：通过，标题与新增/查询操作仍然突出。
- 单次决策：通过，组件没有额外配置步骤。
- 选择数量：通过，AuthImg 内无超过 4 项的选择点。
- 工作记忆：通过，资源状态和记录处于同一行。
- 渐进披露：通过，未增加额外说明面板。
- 组件范围内认知负荷：低；8 项检查没有明确失败。全局菜单组数属于宿主壳层，不记为 AuthImg 缺陷。

## 情绪旅程

成功加载后用户立即看到真实缩略图。慢请求有加载图标，失败不让行高塌陷，这两点降低等待与布局跳动带来的不确定感。失败图标虽能确认“有占位”，但没有重试或原因说明，情绪终点仍是停滞而不是恢复。

## 优点

- 资源切换取消旧请求并校验序号，避免旧图覆盖新图。
- 请求错误、空地址和图片解码失败均有占位，并保留调用方 class。
- 失败尺寸、375px 无横向溢出和 `prefers-reduced-motion` 已有真实浏览器断言。

## 优先问题

1. **[P2] 失败占位对无 alt 调用者只有图片图标**：设备图标和头像宿主未传 `alt`，屏幕上无法区分资源损坏与合法空白。为信息性图片传入描述，或按密度允许的情况下提供清晰失败提示。建议 `/impeccable clarify`。
2. **[P2] 失败后缺少同资源恢复动作**：短暂网络故障后，当前仅切换 `authSrc` 或重新挂载才能重试。若宿主允许，在占位旁提供可访问的重试事件/按钮；若图片纯装饰，则至少明确上层重试契约。建议 `/impeccable harden`。
3. **[P3] 视觉能力与库级组件分叉**：宿主仍直接绑定 Element Plus 的 Loading/Picture，而 `lx-ui` 已有 LxAuthImg/LxIcon。按既定迁移计划，在 Vue3 组件替换波次统一适配，避免逐组件外观漂移。建议 `/impeccable extract`。

## Persona 风险

- **Alex（后台熟练用户）**：缩略图失败后不能对同一资源点一次重试，需重新进入业务编辑/刷新页面，排障路径偏长。
- **Sam（辅助技术用户）**：当 `alt` 为空时失败占位按装饰内容隐藏。对纯装饰缩略图合理，但设备图标、头像若承担识别作用，需要由宿主提供语义替代文本；错误本身没有 live announcement。

## 细节观察

- 失败占位为图标，不带边框或文字，窄表格中占用少；错误语义主要依靠 `alt` 存在时的 aria-label。
- 当前组件加载 spinner 尊重减少动效，避免无限旋转对敏感用户造成不适。
- “重试能力”和“失败占位的可见含义”可分别设计，避免把装饰性图片都变成显眼错误面板。

## 后续问题

- 信息型与装饰型图片是否应由宿主显式区分，并要求信息型场景提供 `alt`？
- transient 失败应由组件重试还是由页面/表单统一恢复？
- 按计划进入 Vue3 组件替换波次时，是否让 AuthImg 适配器直接委托给 LxAuthImg？
