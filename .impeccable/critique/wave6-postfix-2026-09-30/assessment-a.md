# LxTreeSelect 与 LxCascader 独立设计评审

评审对象是两个修复后的 lx-ui 组件及各自 Demo、中文 API 文档。浏览器检查使用本地文档页的桌面视口（截图约 1264 × 720）；评审未读取 Assessment B、detector 输出或旧 Wave 6 报告。

## 设计特异性

业务语境明确：树形选择展示公安组织及禁用节点，级联选择展示组织路径；受控值、异步失败和多选确认都符合管理后台的实际任务。两套组件也沿用 lx-ui 令牌，错误恢复由宿主处理的边界有文档说明。产品特征主要来自数据和交互契约，输入框和弹层的视觉表达仍接近通用后台控件，换到其他管理系统也基本成立。结论是业务特异性较强、视觉特异性中等，足够克制，但还没有形成两者一致的状态语言。

## 整体印象

修复后，Demo 的首要选择控件比状态操作更醒目；真实组织值、空/加载/失败状态以及重试后的结果都便于理解。多选 TreeSelect 的确认机制尤其清楚。最明显的体验缺口出现在失败时：TreeSelect 聚焦后仍突出红色错误边框，Cascader 聚焦后则突出蓝色正常焦点边框，两个同属 lx-ui 的异步选择控件传达了不同的错误优先级。

## 认知负荷

主路径负荷较低：用户先选组织节点或路径，选择结果持续显示；Cascader 的各层选项分步展开，TreeSelect 的组织节点按层级呈现。演示设置默认折叠，避免首次阅读时与主控件争夺注意力。

| 检查项 | 结果 | 证据 |
|---|---|---|
| 单一焦点 | 通过 | 主控件位于示例前部，设置默认折叠。 |
| 信息分块 | 未通过 | 展开设置后，每个示例一次显示 5 个同级控制项。 |
| 分组 | 通过 | 设置项处于同一个带名称的演示控制组内。 |
| 视觉层级 | 通过 | 输入控件最显眼，当前值与状态文案次之。 |
| 一次一项 | 通过 | 选择树节点或逐级选择路径，不需要同时处理多步表单。 |
| 最少选择 | 未通过 | 展开设置后同一决策区有 5 个选项，超过 4 项参考线。 |
| 工作记忆 | 通过 | 当前选择值在控件下方回显。 |
| 渐进披露 | 通过 | 模式、失败和主题等辅助状态默认收起。 |

失败项为 2/8，均来自 Demo 展开后的 5 项状态工具栏；由于这组控件默认折叠且不属于日常选择流程，主路径仍属低负荷。树节点和级联列在单层显示的选项不超过 4 项。

## 情绪旅程

初见时，预置的组织值、可见字段名称和占位提示能让用户迅速理解任务。选择过程中，树层级和级联路径提供稳定上下文；多选 TreeSelect 的“已选数量”及确认/取消按钮让提交时机可预测。失败时，简短错误文字与重试按钮能提供恢复路径；但 Cascader 的蓝色焦点线会弱化触发器上的错误信号，和 TreeSelect 的红色聚焦状态并置时也削弱组件库的可信一致性。恢复完成后的状态文案与当前值回显能重新建立信心。

## 做得好的地方

- 组织树、组织路径和禁用节点让示例具有真实管理语境，选择器不是脱离任务的空壳。
- `loading`、`error`、`retry` 的职责边界清楚，重试由宿主处理；Demo 能展示状态变化和结果回显。
- 键盘焦点、可访问名称、错误播报及多选确认/取消均有实现或文档证据，且状态工具默认折叠，首屏更专注。

## 优先问题

### [P2] Cascader 的错误触发器未呈现与 TreeSelect 一致的错误边界

**影响：** 浏览器中的 Cascader 失败示例获得焦点后，输入框仍显示蓝色焦点描边；TreeSelect 在相同错误场景显示红色描边和焦点 halo。用户仍能看到红色错误文字，但触发器本身给出不同状态优先级。

**修复方向：** 让 `error` prop 在独立使用时也为 Cascader 触发器应用错误边线，并保留清楚可见的键盘焦点；对照 TreeSelect 复核聚焦与未聚焦两态。

**建议命令：** `/impeccable polish`

### [P2] 错误说明没有显式关联到无效字段

**影响：** 两个组件在 Demo 中把 `aria-invalid` 放在控件上，并通过独立的 `role="alert"` 元素显示错误，但没有把错误元素 ID 通过 `aria-describedby` 关联到输入框。读屏用户在错误首次播报后重新聚焦字段时，可能只听到无效状态而拿不到具体原因或恢复提示。

**修复方向：** 为错误说明提供稳定 ID，并确保该 ID 到达实际输入控件的 `aria-describedby`；浏览器复验焦点进入时的可访问名称、无效状态和描述。

**建议命令：** `/impeccable harden`

### [P2] TreeSelect 的错误/重试默认文案不会跟随英文 locale

**影响：** `errorText` 与 `retryText` 默认固定为“加载失败”和“重试”，而空态、加载态等内核文案会根据 locale 处理。英文宿主若仅传入英文 locale，TreeSelect 的失败示例会混用中文；Cascader 的错误和重试兜底则会按中英文切换。

**修复方向：** 让 TreeSelect 的错误及重试默认文案跟随解析后的 locale，同时保留显式文案优先级；补充英文文案行为说明及浏览器示例。

**建议命令：** `/impeccable harden`

## Persona 红旗

- **Sam（键盘/读屏用户）**：浏览器无障碍树能识别 TreeSelect 的“选择组织节点”和 Cascader 的“组织路径”，失败状态有 alert 与可聚焦重试。主要红旗是错误消息没有显式关联到无效输入框；复访该字段时恢复建议可能不可达。
- **Jordan（首次使用者）**：字段名、占位和当前值都能说明选择对象，中文错误也给出重试动作。使用英文 locale 的 TreeSelect 首次遇到加载失败会收到中文“加载失败 / 重试”，造成语言切换和额外判断。
- **Alex（熟练用户）**：筛选和键盘导航有文档说明，Escape 可关闭已打开的面板；多选 TreeSelect 在确认前保留草稿，适合避免误提交。主要剩余成本是复杂组织树依赖逐层展开，没有额外的快捷选择证据；这不是阻断问题。

## 次要观察与验证边界

- 文档说明 375px 下触控目标放大，源码也为窄屏设置了至少 44px 的目标尺寸和弹层宽度约束；本次没有成功把浏览器视口设为 375px，因此这只算源码评估，不是窄屏浏览器验收。
- 两份样式表都有 `prefers-reduced-motion` 规则；本次没有在浏览器模拟减少动效偏好。
- 两个 Demo 的设置工具栏各有 5 个同级控件。默认折叠已减轻首屏负荷，后续可考虑把展示状态与主题选项分组。

## 待综合的问题

- 两种选择器的错误焦点是否应该采用同一套触发器边线和焦点外观？
- 面向英文宿主时，TreeSelect 是否应与 Cascader 一样提供 locale 感知的错误状态默认文案？
- 当业务树很深或用户需要频繁批量选择时，当前逐层导航和显式确认是否仍是最快且最安全的路径？
