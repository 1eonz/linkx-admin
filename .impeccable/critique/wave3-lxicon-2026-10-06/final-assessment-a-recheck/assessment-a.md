# LxIcon 最终页面独立复验

目标：`http://127.0.0.1:4174/components/lxicons.html`。本轮用隔离的 headless Chrome context 检查 1440×1000 桌面和 375×812 移动视口、浅色与深色主题、分组、英文/中文筛选、无匹配态、清除焦点恢复、复制成功与受控的剪贴板拒绝回退。页面由现有本地服务提供，未启动或停止服务。

## 设计特异性判断

**结论：面向 LinkX 的图标目录，具备明确产品语义，不是可直接替换品牌名的通用图库。** 目录把 94 个图形、96 个可用名称、兼容别名及组件用法放在同一页面；卡片同时显示中文用途和 API 名称，符合组件使用者查找并复制代码的任务。`P0 高频核心`、`P1 业务语义` 等术语仍面向熟悉项目分级的开发者。

本报告只记录设计评估 A。确定性扫描、浏览器 detector overlay 及其命中核验由独立 Assessment B 负责；此处不据此宣称 detector 通过，也不把未读到的扫描结果当作零命中。

## 整体印象

本轮确认搜索、分组、清除和复制路径组成了可用的目录；剪贴板失败后的手动复制回退是实际可操作的。当前最大机会是让移动端用户更早看到目录本身，并把动态筛选结果变化可靠地传达给屏幕阅读器用户。

## 做得好的地方

- 初始 7 个原生分组均收起并显示数量；鼠标点击和键盘 Enter 均能展开，输入筛选词后匹配分组自动展开。
- `仪表盘` 搜索匹配到 `dashboard`，成功写入隔离浏览器剪贴板的代码为 `<LxIcon name="dashboard" :size="20" />`，页面显示成功反馈。
- 强制 `navigator.clipboard.writeText` 拒绝后，页面保留可手动复制的代码，文本完整选中且焦点移到 textarea；“清除筛选”清空查询并将焦点还给搜索框。

## 优先问题

### [P2] 移动端首屏主要用于阅读说明，目录入口靠下

**影响：** 375×812 视口中，标题后的图形规格与动效说明占去大半首屏；搜索框位于 y=660，首组标题 y=713，首屏看不到任何图标卡片。初次访问者要先滚动才能开始浏览核心内容。

**建议：** 把首屏说明收敛为一行用途和一个简短示例，将动效/实现细节移到图标目录之后；移动端优先呈现搜索框和首组入口。

**建议命令：** `/impeccable distill` 或 `/impeccable adapt`

### [P2] 无匹配结果没有屏幕阅读器状态播报

**影响：** 筛选实时替换分组；“无匹配图标”是普通 `<p>`，没有 `role="status"` 或 `aria-live`。仅键盘或屏幕阅读器使用者可能不知道查询已变成空结果。

**建议：** 为筛选结果数量或空结果消息提供合适的 `role="status"`/polite live region，并确保每次输入不会逐字造成冗余播报。需要用真实屏幕阅读器复验播报频率和清除后的结果提示。

**建议命令：** `/impeccable audit`

### [P2] 复制失败时有两个 assertive alert，可能重复播报

**影响：** 强制剪贴板拒绝后，目录中的回退面板有 `role="alert"`，同时 `lxMessage.error` toast 也有 `role="alert"`；Playwright 的 `[role="alert"]` 严格定位器实际命中两个区域。两条文案都说明复制失败和手动复制，屏幕阅读器可能连续读出重复信息。

**建议：** 只保留一个 assertive 告警；另一个可作为普通可见提示，或移除重复 toast 内容。修改后用至少一种屏幕阅读器确认失败信息只播报一次，且选中代码仍可被用户理解和复制。

**建议命令：** `/impeccable audit` 或 `/impeccable clarify`

## 认知负担

判定：**中等（2 项失败）**。

- 通过：主任务明确；内容按语义分组；搜索、名称和用途并列可识别；单次操作只有“搜索/展开/复制”；不需要跨页面记忆信息；未筛选时图标卡片采用渐进披露。
- 失败：桌面目录首层仍展示 7 个类别，高于参考的每决策点 4 项上限；移动端导语占据首屏大部分，使操作入口后置。
- 边界：展开 `P2 通用补充（29）` 后会一次呈现大量卡片；搜索能降低扫描成本，但不是所有用户都会先知道可以搜索。
