# LxPasswordInput 独立设计与 UX 评审

评审目标：`http://127.0.0.1:4182/components/lxpasswordinput`，对照文档 `linkx-fe/docs/components/lxpasswordinput.md` 与示例 `linkx-fe/src/components/LxPasswordInput/demo/basic.vue`。

## 设计特异性

**判断：中等偏高，业务语义具体，文档外壳通用。** 密码显隐、离开后遮罩、密码管理器剪贴板策略以及只读/禁用态都贴合 LinkX 的敏感凭据场景；示例的中文说明也能解释组件默认值与 Demo 覆盖值的区别。视觉骨架仍是常见 VitePress 文档页，品牌主要靠 `LxUI` 名称和 HUD 深色预览表达，HUD 控件还藏在折叠区。若移植到其他组件库，页面结构几乎无需变化。

整体阅读顺序清楚：用途说明、交互示例、Props/Events/方法/使用边界。桌面左右导航加中间正文也符合组件文档预期。主要不一致来自暗色文档主题下 Demo 仍保留白色表面，以及窄屏目录锚点对标题的定位。

## 情绪路径

进入页面时，简短用途说明和“访问密码”字段让敏感输入场景容易识别。探索阶段可直接切换显隐、尺寸和离开遮罩，默认值说明与安全提示让人知道当前 Demo 和组件 API 默认值并不相同。显隐阶段的 `aria-pressed`、可见眼睛图标和失焦后重新遮罩带来控制感；结束时 Live Region 会记录最近操作。两处打断信任感的地方是 320px 目录锚点遮住章节标题，以及暗色页面中突兀的白色示例面板。

## 优势

1. 安全语义讲得准确：组件默认 `maskOnBlur=false`，Demo 显式启用并说明原因；剪贴板策略也区分前端事件拦截与真正的安全边界。
2. 示例状态覆盖有实用层次：基本设置直接可见，剪贴板/HUD 采用渐进披露；只读、禁用和实例方法各有具体样例。
3. 键盘及窄屏基础可靠：键盘操作可切换显隐，焦点离开后恢复遮罩；320px 参数提示出现，参数表自身可横向滚动，文档页宽没有外溢。

## 优先问题

1. **[P2] 320px 目录锚点遮住“交互示例”标题**：真实锚点把标题定位到 `top=0px`，48px 高的 `VPLocalNav` 覆盖标题；标题的 `scroll-margin-block-start` 为 `0px`。Demo 面板本身定位正常，`top=80px`，与导航栏底边相隔 32px，但面板上的 margin 不会保护前置标题。给章节标题/锚点加与吸顶栏匹配的滚动边距，并复验从 “On this page” 进入的结果。建议命令：`/impeccable adapt`。
2. **[P2] 暗色文档页里的 Demo 保持白色**：1280px 暗色页面主体背景为 `rgb(27, 27, 31)`，Demo 背景仍为 `rgb(255, 255, 255)`；HUD 开关可把面板切成 `rgb(16, 26, 44)`，说明深色方案存在，但普通暗色页面没有跟随系统主题。让 Demo 的 Element Plus 主题变量映射文档暗色令牌，或明确呈现这是独立浅色预览。建议命令：`/impeccable adapt`。
3. **[P3] 手机 Demo 设置项只有 32px 高**：320px 下四个工具栏标签实测高度均为 32px。它们有整行标签可点，超过 WCAG 2.2 AA 常见 24px 最小目标尺寸，因此不是合规阻断；但低于更舒适的 44px 移动触控目标建议。可在窄屏将标签高度增至 44px，同时保留当前换行布局。建议命令：`/impeccable adapt`。

## 角色风险

**Sam（键盘/辅助技术用户）**：Tab/Shift+Tab 能让显隐按钮获得 2px 可见焦点，Space 可显隐，`aria-pressed` 随状态变化；失焦后遮罩恢复。风险是目录锚点滚动会让视觉章节标题被固定导航遮挡。未运行屏幕阅读器，ARIA 朗读实际表现仍需独立验证。

**Casey（移动端、单手使用）**：375px 与 320px 下示例选项自然换行，页面本身不横向滚动，参数表也有可用的水平滚动区域。32px 高的设置标签略小于推荐触控高度；320px 章节定位时标题被导航盖住，会增加回看成本。

**Jordan（初次使用者）**：中文字段与状态说明直白，初始 Demo 的遮罩行为有说明。风险是 `HUD` 缩写没有定义，且“离开后遮罩”属于 Demo 启用、组件默认关闭，首次阅读者需要同时理解这两个状态；当前说明基本能区分，但可再让差异更醒目。

## 次要观察

- 320px 参数表提示可见，表格滚动 `scrollLeft` 从 0 到 100；表格宽 917px，视口容器宽 272px，页面宽仍是 320px。滚动后行名列离开视野，返回左侧时仍可恢复。
- 减少动效媒体查询命中；显隐按钮与折叠图标的 `transition-property` 均为 `none`，Demo `scroll-behavior` 为 `auto`。
- HUD 深色面板文本为浅色，字段轮廓清晰；普通暗色页面与 HUD 模式看起来像两个不相连的主题状态。
- 浏览器有一次 `/favicon.ico` 404 控制台提示；未观察到页面异常或其他响应错误，它不影响本次组件评审。

## 浏览器边界

使用全新 Playwright browser/context/page，通过 Playwright Chromium driver 驱动 Chrome 154。检查了 1280×900、375×812、320×800，浅色/暗色文档、HUD 开关、320px Props 滚动、章节锚点与 Demo 面板偏移、键盘焦点/Space 显隐/Tab 失焦遮罩、`prefers-reduced-motion: reduce`。本次没有覆盖真实触屏设备、VoiceOver/NVDA、Firefox/WebKit、200% 缩放或后端流程。4182 服务保持运行。

## 结论

设计语义和键盘交互表现可信，移动页面宽度与参数表滚动正常；评估为 **29/40（Good）**。下一轮应先修章节锚点标题被遮挡，再决定 Demo 暗色页面的主题契约。32px 工具项标签是可改善的触控舒适度问题，不构成合规阻断。
