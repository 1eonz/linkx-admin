# Element Bridge 多选焦点独立评审（当前 inset 样式）

## 方法与范围

- 目标：`http://127.0.0.1:4174/components/element-bridge.html`，聚焦“协同部门”多选控件。
- 本次实际源码为 `linkx-fe/src/styles/element-theme.css` 的 `.el-select__wrapper.is-focused`：单层 `2px` inset `box-shadow`，`outline: none`；错误焦点使用 `--lx-color-error-strong`。不是 `outline-offset: -2px` 版本。

- 多选错误态只在隔离浏览器中给该表单项临时添加 `is-error`，用于检查红色焦点样式；Demo 没有给“协同部门”配置校验规则。截图不代表真实多选校验、错误文案或提交流程。

## 焦点轮廓结论

**通过：当前 inset 方案在本轮覆盖的八种状态下是一条贴合控件边缘的焦点线，不像双框，也没有外扩光晕。**

- 普通焦点计算样式为一层 `2px inset` 阴影；浅色使用 `#0060a9`，HUD 使用 `#38bdf8`。错误聚焦使用 `#c45656` / HUD `#f78989` 的一层 `2px inset` 阴影。四种状态均为 `outline: none`，没有第二层 `box-shadow`。
- 截图中颜色线沿 4px 圆角的控件边缘呈现为单一轮廓；没有和原控件边线分离的外圈。计算尺寸在桌面为 `287×32px`，375px 下为 `301×32px`，普通与错误聚焦前后不变。
- 八种状态按 Escape 后 `aria-expanded` 均回到 `false`；在窄屏浅色普通态另等候关闭过渡，确认弹层尺寸归零且不再可见。关闭过渡期间短暂保留的 popper DOM 不应算作仍可见的弹层。
- 因此，对“外圈/双框是否仍存在”的明确结论是：**当前实测截图通过，不建议为这个现象继续改焦点边线。** 这只覆盖此页面的单选/多选 wrapper 在两种主题、两种宽度下的状态。

## 设计特异性

**中等偏强。** 中文表单、HUD 主题、LinkX token 和 Element Plus 接入边界使它明显属于 LinkX 组件文档；但演示面板仍采用熟悉的通用组件展示方式，品牌个性主要来自主题和控件细节。对开发者验收页来说，克制是合适的，关键状态比品牌装饰更重要。

## 认知负荷与情绪旅程

- 被测多选只有三个可见选项，没有超过四项的决策负担；375px 下页面没有横向溢出。六种按钮是展示变体，不是六个并列业务决策。
- 一项清单失败：375px 下弹层向上展开，覆盖“协同部门”标签 `51×17px`。弹层范围为 `x=38, y=646, 299×114px`，标签为 `x=37, y=743, 52×22px`；前一个“任务名称”字段结束于 `y=645`，没有被弹层遮住。
- 普通聚焦时标签折叠和值留在控件内，焦点边线传达状态；打开菜单时标签短暂被遮住，用户需要依靠当前已聚焦的控件和三项列表维持上下文。Escape 关闭后回到稳定状态。

## 做得好的地方

1. **焦点边线已收敛为一个轮廓。** 当前实际源码和八张新截图一致：一层 inset 线，没有额外外环；两种主题的错误色也没有叠出第二圈。
2. **焦点状态不改变控件几何。** 桌面 `287×32px`、375px `301×32px`，普通与模拟错误聚焦相同。
3. **主题和关闭操作可辨认。** 浅色/HUD 的焦点颜色差异清楚，Escape 会关闭多选菜单，已选标签没有丢失。

## 优先问题

### [P2] 375px 下的多选菜单遮住本字段标签

- **影响：** 选项列表展开后遮挡 `协同部门` 标签 `51×17px`，用户暂时失去该组选项的文字上下文。遮挡的是当前字段标签，不是前一个任务名称字段。
- **建议：** 调整窄屏展开后的滚动位置或弹层布局，确保字段标签仍可见；若菜单必须向上展开，可在菜单内重复字段名称。保留现有 Escape 关闭行为。
- **建议命令：** `/impeccable adapt`。

### [P2] 错误提示文字 token 对比度不足

- **影响：** `--lx-color-error-strong` `#c45656` 与 `--lx-color-error-light` `#fef0f0` 的对比度为 `3.93:1`；LxForm 错误文字为小字号，未达到普通文本 `4.5:1` 的 WCAG AA 基线。
- **边界：** 本轮多选错误是临时 `is-error` 样式模拟，截图没有真实多选错误文案；此项是错误文字 token 的实测配色问题，不代表协同部门已经有校验规则。
- **建议：** 只加深错误文字色，保留当前错误边线颜色；验证浅色和 HUD 错误提示的文字对比度。
- **建议命令：** `/impeccable colorize`。

### [P3] 下拉选项行高为 34px，高于 32px 设计契约

- **影响：** 三条选项实测各为 `34px`，比表单控件设计参考 `32px` 高 `2px`；当前短列表可以使用，但同一控件在紧凑表单中的节奏不一致。
- **建议：** 对齐 Element Plus 选项行的上下 padding/line-height 至 32px，再复验 hover、选中和 HUD 状态。
- **建议命令：** `/impeccable polish`。
