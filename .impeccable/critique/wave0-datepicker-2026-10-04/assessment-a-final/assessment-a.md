# LxDatePicker 独立设计评估（Assessment A）

**评审目标**：`linkx-fe/src/components/LxDatePicker/index.vue` 及其 Demo/文档。按日期选择器实际操作路径评估，模式为 Operate；文档页作为组件示例与说明场景一并观察。此报告仅记录 Assessment A 的设计判断，没有读取或合并 Assessment B 的 detector / overlay 证据。

## 设计特异性

这是一个有产品语境的通用控件，而不是任意后台中原样可换的日期框：32px 触发器、LinkX 主色与等宽值文字、周一起始、中文“至”、标本 06 的浅蓝范围带，以及“布控生效日期 / 研判时间范围 / 告警汇聚窗口”等文案共同指向 LinkX 管理场景。它也正确地保留了 Element Plus 的日期网格和熟悉的翻月方式，没有为“独特”牺牲常见日期操作预期。

个性主要在语义、令牌和日期规则；日历面板骨架仍然是熟悉的组件库形态。这对高频管理工具是合理的取舍。当前最值得补足的不是装饰，而是让移动端快捷选择、键盘区间和 HUD 状态也达到同等完整度。

## 认知负荷

八项清单有 **1 项失败，整体为低认知负荷**：

| 检查项 | 结果 | 观察 |
|---|---|---|
| 单一焦点 | 通过 | 打开后核心任务仍是选日期；旁侧/下方说明不会制造第二个必答决定。 |
| 分块 | 通过 | 周表按行分组，Demo 按单值、区间、快捷项等模式分节。 |
| 分组 | 通过 | 日期、星期、快捷项和表单标签各自成组。 |
| 视觉层级 | 通过 | 当前月、星期标题、范围带和端点状态可辨。 |
| 一次一事 | 通过 | 用户可先选日期，再确认区间，不必同时填写额外字段。 |
| 最少选项 | **失败** | 单月日历一次可见约 35 个日期格，超过 4 个选项；这是日期选择的固有面板，周行分组和三个快捷项提供了一定缓冲。 |
| 工作记忆 | 通过 | 当前值和选中范围仍显示在触发器/日历中，不要求记住前一屏内容。 |
| 渐进披露 | 通过 | 日历在聚焦/点击后才展开，低频 API 能力留在文档表格和透传段落。 |

## 情绪路径

用户从已有日期或范围进入，当前值和周历立即给出方向；选中后的端点、范围带及状态文案提供确认感。`今日 / 本周 / 近30天` 能成为高效的正向峰值。挫折点出现在两类用户：手机用户打开带快捷项的日历后需要横向滚动；键盘用户从区间输入按 ArrowDown 后仍停留在输入框，不能沿承诺路径继续选日。选择完成后的值回显和状态播报让结束点清楚，但错误恢复情境仍未在 Demo 展示。

## 做得好的地方

- 周一起始由组件局部中文 locale 提供，不污染宿主全局 locale；这同时让日期表头和“本周”预设遵循同一约定。
- 范围选取把起止点和连续区间带并列呈现，桌面双月可独立翻页，快速判断日期落点不必在两次打开中来回切换。
- Demo 覆盖单值、月份、区间、预设、标记、日期时间、禁用与只读多种实际形态，并以布控、研判、告警的业务文案解释差异。

## 优先问题

1. **[P1] 390px 下带快捷项的弹层扩大页面宽度**
   - **证据**：触屏视口设为 390px，打开“研判时间范围”后弹层为 440px、左对齐在 `x=0`；根文档 `scrollWidth=441px`。不带快捷项的主区间弹层为 324px，未发生页面溢出。
   - **影响**：手机上日期网格和快捷项不能同时留在视口内，页面出现横向滚动，单手选择不稳定。
   - **建议**：窄屏将快捷项收为顶部菜单/选择项，或把侧栏改为日历上方的紧凑分段控件；弹层宽度必须受视口约束。
   - **建议命令**：`/impeccable adapt`

2. **[P1] 区间输入按 ArrowDown 后焦点没有进入日期网格**
   - **证据**：从“专项布控日期区间开始日期”聚焦并按 ArrowDown，弹层可见但 `td:focus` 数量为 0，`document.activeElement` 仍是 `#demo-date-control-start`。单值路径能将焦点送入一个日期格。
   - **影响**：区间用户不能按文档所述使用方向键移动并按 Enter 选日；键盘用户需要转为鼠标/触屏或寻找未说明的旁路。
   - **建议**：区间输入打开日历后将初始焦点放到当前选中日/有效日期格；范围起止状态也应能被读屏识别。
   - **建议命令**：`/impeccable audit`

3. **[P2] 手机日历格与月份箭头的触控区域偏小**
   - **证据**：390px 触屏下日期格约 `41.7 × 44.5px`；前/后月按钮各约 `24 × 16px`。项目可访问性要求以至少 44px 触控目标为参考。
   - **影响**：相邻日期或翻月按钮不易单手精确点按，尤其是连续翻月时。
   - **建议**：扩大实际按钮命中区域至至少 44 × 44px；日期格同时将宽度补足到 44px，或用不增加面板宽度的内层触控伪元素承接命中。
   - **建议命令**：`/impeccable adapt`

4. **[P2] HUD 深色示例中的日期输入仍为白底**
   - **证据**：主题切换后弹层背景为 `rgb(22, 35, 58)`，Demo 背景为 `rgb(11, 18, 32)`，日期输入 wrapper 仍为 `rgb(255, 255, 255)`；截图中白色触发器明显切断深色面板。
   - **影响**：示例宣称的深色状态没有贯穿同一控件，使用者会误判组件是否支持该主题，也难以评估实际深色组合。
   - **建议**：让输入触发器与 Popper 共用主题令牌；若此开关只演示弹层主题，应收窄开关名称和示例范围。
   - **建议命令**：`/impeccable polish`

## 人物路径红旗

**Alex（熟练用户）**：单值输入从 ArrowDown 进入日期格，具备直接键盘路径；但相同操作用于区间只打开弹层，焦点仍留在开始输入，熟练用户无法按左右键快速移动日期。三个预设可加速常见范围选择。

**Sam（键盘 / 读屏用户）**：单值路径的日期格有焦点反馈；区间开始输入未把焦点送入网格，是主要阻断点。翻月按钮命中尺寸只有 24 × 16px；本次未使用屏幕阅读器，读屏行为不作通过结论。

**Casey（移动单手用户）**：常规区间单月面板在 390px 内完整显示；含快捷项时面板宽 440px 并令页面滚动宽度达到 441px。日期格宽度不足 44px，翻月仅 24 × 16px，连续选取与换月都容易误触。

## 次要观察与问题

- Demo 的中文提示相当完整，适合作为组件档案；实际展开日期面板时仍能看到较长的说明文案，学习页的阅读密度高于日常业务表单。
- 桌面单月面板约 324px；移动单月区间在 390px 下为 324px 并居中，边距稳定。双月区间沿用横向展开，适合桌面，不宜直接搬到手机宽度。
- 快捷项为三项，数量本身在低负荷范围；溢出来自“左侧侧栏 + 日历”的组合宽度，不是选项数过多。
- 浏览器控制台有一条未定位来源的 404 资源日志；本评估没有把它归因为日期选择器缺陷。

## 可以继续追问

- 手机上最常用的是“本周/近30天”还是任意日期？快捷项能否先于日历显露，同时保持弹层不超过视口？
- 区间键盘入口应把焦点放到开始日期、当前端点还是首个有效日期，并如何让读屏用户听到这一状态？
- HUD 开关要模拟完整控件主题，还是只呈现弹层配色？当前命名和白色触发器传达了不同答案。
