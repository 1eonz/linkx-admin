## 当前计算样式

当前工作区源码（`linkx-fe/src/styles/element-theme.css:140`）仍为：

- `.el-select__wrapper`：`border-width: 0px`、`box-sizing: border-box`、`padding: 4px 12px`。
- 普通态：`box-shadow: rgb(228, 231, 237) 0px 0px 0px 1px inset`（HUD 普通态为主题灰色 inset 线）。
- 聚焦/展开：浅色 `rgb(0, 96, 169) 0px 0px 0px 1px inset`；HUD `rgb(56, 189, 248) 0px 0px 0px 1px inset`。
- 聚焦态 `outline-style: none`，控件尺寸保持桌面 `287×32px`、375px `301×32px`、390px `316×32px`。
- wrapper 的几何左边为 `x=353`（桌面）或 `x=37`（移动），但可见 inset 线从几何边缘向内约 1px；这正是用户所说“外圈与自身 border 没有对齐”的残留来源。当前不是额外外扩阴影造成的双圈，而是线条落在内缘。

## 视觉结论

焦点没有额外的 `outline` 或外扩 `box-shadow`，双圈问题已消失；但当前解决方案把状态线画成 inset 阴影，而元素本身没有 1px border。因此焦点线不会覆盖控件最外一圈，背景与线之间形成 1px 内缩感。浅色中不明显，HUD 和卡片边界附近更明显。建议将状态线落实为真实 `border: 1px solid`，同时保持 `box-sizing: border-box`、尺寸不变，聚焦只切换 `border-color`，并移除选择器相关 inset 阴影；错误态采用同一真实边框承载错误色。

## 优先问题

### [P1] 选择器焦点线仍未与控件几何外缘对齐

- **证据：** 六个主题/视口均计算为 `border: 0`，聚焦只有 `0 0 0 1px ... inset`；`browser-evidence.json` 的 `rect` 与 `boxShadow` 可复核。
- **影响：** 需要对齐设计稿和相邻输入框时，线条向内退 1px，圆角处尤其明显；用户会继续看到“外圈”与控件自身边缘不是同一条线。
- **修复：** `.el-select__wrapper { border: 1px solid var(--lx-border); box-sizing: border-box; }`；普通、hover、focus、error 仅更新 `border-color`，删除选择器 `box-shadow`，保留尺寸回归断言。
- **建议命令：** `/impeccable polish`。

### [P2] 375px/390px 上翻弹层覆盖当前字段标签

- **证据：** 375px 测得字段标签 `y=743..765`，弹层 `y=646..760`，重叠约 `17px`；390px 标签 `y=663..685`，弹层 `y=566..680`，同样重叠约 `17px`。页面 `scrollWidth === clientWidth`，不是横向溢出。
- **影响：** 用户展开菜单时暂时看不到“协同部门”字段名，第一次使用或快速切换时需要记住上下文。
- **修复：** 移动端打开前滚动字段到弹层下方可见的位置，或在上翻弹层头部复述字段名；保留 44px 触控目标并复验 375/390。
- **建议命令：** `/impeccable adapt`。

### [P3] 选项行高仍为 34px

- **证据：** 三个 `.el-select-dropdown__item` 均实测约 `33.99px`，`line-height: 34px`；设计参考要求密集列表按 `32px/项`。
- **影响：** 移动端弹层占高增加，进一步挤压字段标签和上下文。
- **修复：** 仅调整选项 padding/line-height 到设计令牌的 32px，并复验选中、禁用和键盘 hover。
- **建议命令：** `/impeccable polish`。
