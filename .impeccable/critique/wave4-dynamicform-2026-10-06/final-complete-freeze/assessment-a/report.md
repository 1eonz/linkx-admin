# LxDynamicForm Assessment A

## 范围与证据

本报告是独立设计评估 A，只依据 Assessment A 的冻结浏览器证据；未读取 Assessment B 或 Detector 结果。目标是 `http://127.0.0.1:4174/components/lxdynamicform.html`，即 LxDynamicForm 文档页中的交互示例。评估模式以 Read 为主，包含嵌入式 Operate 演示。

使用 Chrome 154.0.8037.95 检查 1440×1000 桌面与 375×812 窄屏，页面均返回 HTTP 200。桌面文档尺寸为 1440×7352，窄屏为 375×9602；窄屏文档宽度等于视口宽度，没有页面级横向溢出。完整截图和交互采样保存在本目录。

已观察到：任务信息、任务状态、附件分组；空表单提交显示两个必填错误；填写任务名称和密码后页脚显示校验成功，输入仍保留，恢复截图中的字段不再显示红框或错误；上传失败给出重试操作，重试后显示成功；字段类型预览可键盘打开，14 种类型可搜索，搜索“密码”后只剩“密码输入”，键盘选择可切换密码和上传预览。375px 下提交与重置按钮高 44px。

证据存在一处采样冲突：`browser-evidence-desktop.json` 的 `required-fields-recovery.fieldErrors` 仍列出旧错误，但 `desktop-form-recovered.png` 中错误样式已消失，页脚为成功提示。按截图和页脚判断恢复成功；旧错误列表不作为产品缺陷计分。Mock 上传失败在浏览器控制台产生预期的 `UploadAjaxError`，同时记录的 HTTP failures 为空。

## 认知负荷

8 项检查中 1 项失败，整体认知负荷低。分组将 4 个任务信息字段、1 个状态字段和 2 个附件字段分开；标题、说明、交互示例和代码区有清楚层级。低频设置默认收起，字段预览默认折叠，主要任务不要求记住前页信息。唯一超出 4 项原则的决策点是展开后的 14 种字段类型选择；可搜索输入能快速缩小选项，但列表本身没有类别分组。

## 优点

- 文档由简短的最小配置进入实际表单示例，页面信息架构适合正在集成组件的开发者。
- 错误、成功和恢复状态都有具体文案；重试后只更新上传状态，不清除其他表单输入。
- 窄屏没有页面级横向溢出，表单字段纵向排列，主要操作按钮达到 44px 高。

## 优先问题

1. **P2，辅助技术命名需确认。** 可见字段标签正常，但浏览器证据中 4 个输入的原生 `labels` 和直接 `aria-label` 均为空；采样没有记录 `aria-labelledby` 或计算后的 accessible name，因此不能据此断言缺陷，也不能给出无障碍通过结论。建议核对计算名称及屏幕阅读器朗读，并为标签关联补回归验证。
2. **P2，字段类型目录的选项较多。** 展开后一个选择器包含 14 项，虽然可搜索且键盘选择已验证，初次使用者仍需在同一列表中辨认较多不同概念。可在不改变搜索行为的前提下按输入、选择、日期、反馈等 schema 类别分组。
3. **P3，窄屏示例需要较长滚动。** 交互表单位于文档页较深处，采样中页脚按钮位于文档坐标约 y=2392，整页约 9602px 高。右侧章节目录在移动端折叠为页内导航，能缓解定位，但中断后回到示例仍需重新定位；这对文档浏览影响有限，不代表生产表单问题。

## Persona 风险

- **Jordan，初次使用者：** 任务字段和说明直观，最小配置代码提供入口；14 种字段类型缺少类别线索，理解 schema 术语仍依赖目录说明。
- **Sam，辅助技术用户：** 已验证字段选择器能键盘打开、搜索和选择；未运行屏幕阅读器或 200% 缩放测试。字段可见标签与其计算 accessible name 的关系尚未由当前采样证实。
- **Casey，移动用户：** 375px 页面无横向溢出，按钮 44px 高；演示位置较深且状态未覆盖离页后恢复，适合文档试用但不应据此推断实际业务表单适合中断场景。

## 情绪路径与边界

用户先看到组件用途和最小代码，再进入可操作表单；空值报错明确，修正后有成功确认。上传失败状态提供了直接恢复出口，结束情绪稳定，没有因 Mock 失败而丢失已输入字段的迹象。

未覆盖屏幕阅读器、计算对比度、200% 缩放、320px 视口、真实移动浏览器、完整整页键盘遍历、减少动效偏好及真实后端上传。上传交互是文档 Mock，HTTP 无失败记录不代表后端联调通过。字段恢复 JSON 与截图冲突已如上记录。

**评审问题：** 字段类型预览是否继续保留单一 14 项目录，还是在列表内按 schema 类别分组，同时保留现有搜索和键盘选择？
