# Assessment A：LxDynamicForm 与 LxUpload

评估目标：`http://127.0.0.1:4174/components/lxdynamicform.html`  
评估时间：2026-10-06  
浏览器：Playwright 驱动的 Chrome 154.0.8037.95。Playwright 缓存 Chromium 因 Windows 并行配置错误无法启动，改用机器已安装的 Chrome。  
冻结核验：34 个文件在评估前、后均与 `source-hashes-freeze.json` 匹配；见 `hash-verification-before.json`、`hash-verification-after.json`。

## 设计特异性

这不是完全可互换的通用组件页：交互示例以任务巡防为场景，包含任务名称、访问密码、类型、负责人和图片附件；远程候选项与上传错误恢复也对应组件真实的扩展边界。组件库侧栏、章节导航和 API 参考表让内容易定位。

整体构图仍沿用常见的 VitePress 文档结构，代码块、交互示例和长 API 表格占据主要篇幅，LinkX 自身的视觉性格主要来自站点外壳与组件令牌。机会在于让开发者更快进入可操作示例，并把字段类型预览按用途组织。

## 整体印象

表单示例有实际语义，窄屏仍保持可读，错误恢复是最完整的部分。最值得改善的是任务信息的分组和字段类型预览的选择负担。桌面、375px 与 320px 视口的页面宽度分别为 1440、375、320px，没有页面级横向溢出。

## 做得好的地方

- 任务信息与附件分组明确；桌面两列在窄容器收为单列，字段标签仍可读。
- 提交空表单后，“任务名称”“访问密码”的错误显示在对应字段附近，并保留所有其他表单值。
- LxUpload 与远程候选查询都有内存 Mock 失败态和贴近字段的重试；上传重试保留文件项并切换为成功，候选重试恢复 3 个选项。

## 优先问题

1. **[P2] “任务信息”下有五项可见输入/开关。** 在小屏上，名称、密码、类型、负责人和启用状态纵向连续出现，超出每组四项的认知负荷建议。把启用状态移到独立的“任务状态”组，或拆分信息组。建议命令：`/impeccable layout`。
2. **[P2] 字段类型预览包含 14 种类型。** 冻结 schema 列出了 14 个类型；展开选择器时用户需要在一处扫过全部类型。对首次接触组件的开发者，按用途分组或给选择器加搜索会更易找。自动化未能拍到展开菜单：滚动到控件后，固定导航/控件占位层拦截了 Playwright 点击；菜单窄屏尺寸和键盘展开仍待人工确认。建议命令：`/impeccable clarify`。
3. **[P3] 必填错误与底部状态提示重复。** 两条字段错误出现后，表单底部又显示“请填写标红的必填字段”。可保留字段错误，仅在底部汇总错误数量或提供跳转，减少重复阅读。建议命令：`/impeccable distill`。
4. **[P3] 文档站点请求 `/favicon.ico` 返回 404。** 页面内容完整且没有可见布局影响；补齐站点图标或移除此请求。建议命令：`/impeccable audit`。

## 认知负荷

按 8 项清单检查：单一焦点、相关分组、视觉层级、逐项决策、工作记忆和渐进披露通过；“任务信息”五项分组确认失败；最少选项项待确认，字段类型列表按冻结 schema 有 14 项，但浏览器未成功展开菜单。当前按中等风险处理，等待核查菜单实际显示与窄屏定位后再定级。

已观察的主要决策点中，任务类型只有 2 项；候选人员模拟有 4 种状态。另有 14 项字段类型选择，属于预览控件而非默认显示内容。

## 情绪流程

初始表单让开发者迅速理解字段如何组合；提交空值时，红色边框、字段旁错误和底部提示一起构成较重的情绪低点。附件与远程选择失败都保留现有值、指出问题并给出重试入口，重试后状态明确恢复，是流程的安心点。结束反馈可减少重复，文档也可缩短从入口到示例的距离。

## Persona 红旗

**Jordan（首次使用者）**：主表单标签和验证文案清晰；但文档开头直接使用 `schema`、`props`、`v-model`、TSX 等术语，没有面向首次使用组件者的简短解释。TA 能完成表单示例，读懂字段契约可能需要往返查阅表格。

**Sam（键盘/辅助技术用户）**：实测 Tab 顺序经过名称、密码、密码显隐、类型、负责人、开关和上传入口，焦点环可见；校验错误在字段旁，上传状态有文字。实际读屏器播报未验证，尤其是上传的 live status 与 14 项类型选择器需补一轮 AT 检查。

**Casey（移动用户）**：375px 和 320px 下无页面横向溢出，上传区与主操作仍可点击。表单按单列展开，两个文件区和列表把“提交校验/重置”推到表单末尾；中断后返回需要重新滚到操作处，当前没有固定或重复操作入口。

## 次要观察与待核查

- 预期的上传 Mock 首次失败在控制台出现 `UploadAjaxError: 上传失败，请重试`；没有失败网络请求，也没有真实后端调用。该错误用于演示，不等同于未捕获的业务失败。
- `/favicon.ico` 的 404 已定位，但不影响页面内容。
- 组件页内存 Mock 验收不代表真实上传、权限或后端联调；这些不属于本轮浏览器体验结论。
- 待核查：用人工滚动或键盘打开 14 项字段类型选择器，确认固定导航没有遮挡，检查 320px 弹层边界；再用 NVDA/VoiceOver 核实错误、上传状态和候选查询的播报。
