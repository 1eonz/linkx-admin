# DynamicForm / LxUpload / 日期范围设计评审

评审对象为 `http://127.0.0.1:4174/components/lxdynamicform.html` 及统一冻结清单内的 33 个源文件。桌面视口为 1440×1000；移动视口为 375×812 CSS px、DPR 2，并启用 CDP 触屏、`pointer: coarse`、`hover: none` 和 `prefers-reduced-motion: reduce`。浏览器使用临时隔离 profile 与新建 CDP browser context。页面返回 HTTP 200，动态表单已渲染。

## 设计具体性

交互内容有明确的组件库开发语境：中文 schema 表单、远程人员候选、附件上传、日期范围，以及受控值和 Mock 状态说明，整体比可换名复用的通用表单 demo 更具体。字段按“任务信息 / 附件”分组，错误和远程反馈贴近对应字段。页面外层仍是常见文档站结构；移动端工具栏保留英文“Menu”和“On this page”，与主体中文不一致。

## 整体印象

表单主体的结构和反馈完整，开发者能从文档进入一个可操作的组件示例。验证失败后的字段定位和远程失败状态比较明确。最明显的改进空间在移动端示例的操作距离，以及文档工具栏的语言统一。没有确认到阻断核心操作的问题；日期范围弹层和上传重试因交互未到达结果，不能视为通过。

## 做得好的地方

- 字段标题、必填提示、任务分组和两列到单列的变化符合表单填写顺序；375px 下文档页 `scrollWidth` 为 375px，没有横向溢出。
- 空表单提交后，两个必填错误显示在字段附近，首个错误输入获得焦点；已观察到“请输入任务名称”和“请输入访问密码”。
- 远程失败文案“候选人员读取失败”和“重试”出现在负责人字段旁；上传默认成功和上传失败样例都有文字状态，失败行保留文件名和错误说明。

## 优先问题

### [P2] 中文文档页的移动导航仍显示英文

**影响：** 375px 截图的固定顶部栏显示“Menu”和“On this page”，其余文档为中文；首次使用者需要额外翻译导航语义。

**建议：** 将移动菜单和页内导航标签本地化为简体中文，并检查桌面右侧页内导航保持相同语言。

**建议命令：** `/impeccable clarify`

### [P2] 移动端主要操作离表单起始较远

**影响：** 375×812 视口下，交互示例约 1306px 高，提交/重置区域位于 demo 内 y≈1240px；填写者完成字段后仍需滚动才能提交，上传列表增高时距离会继续增长。

**建议：** 为窄屏提供可见的提交入口，或缩短文档示例里的演示字段；若采用吸底动作栏，应验证它不遮挡上传列表和校验错误。

**建议命令：** `/impeccable adapt`

### [P3] 上传失败示例把 Mock 实现术语放进错误文案

**影响：** 页面直接显示“文档 Mock 上传失败”。在演示页中这能说明数据来源，但错误反馈本身更像实现日志，削弱了面向组件使用者的错误示例质量。

**建议：** 错误状态使用“上传失败，请重试”等用户语言；“此示例使用本地 Mock”保留在示例说明中。

**建议命令：** `/impeccable clarify`

### [P3] “HUD 深色主题”缺少上下文说明

**影响：** “HUD”出现在设置项中但没有解释，首次阅读组件文档的开发者可能不清楚它与常规深色主题的区别。

**建议：** 将开关标为“深色主题（HUD）”或在相邻设置说明里定义 HUD。

**建议命令：** `/impeccable clarify`

## 认知负荷

8 项检查中，7 项通过、1 项未通过，整体为**低认知负荷**。单一焦点、分组、层级、逐步披露和工作记忆负担都得到字段分区、折叠设置及折叠类型预览的支持。失败项为“最少选项”：字段类型预览集中浏览 14 个类型，超过建议的 4 个可比较选项；源示例说明这是逐项查看控件的入口，但可考虑按常用/高级分组或提供搜索。候选状态的 4 种模式已独立分组，数量本身在界限内。

## 情绪路径

进入示例后，任务字段和上传区有明确标题；提交空表单时能快速看到具体错误并定位到首字段。远程失败状态靠近负责人输入，能减少对“哪里失败”的猜测。移动端滚动到提交区前的等待，以及实现术语出现在错误文案里，是主要的轻微挫折点。日期范围选择流程没有到达可见弹层，故不评价其完成体验。
