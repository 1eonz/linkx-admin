# Wave 5 Assessment A：LxDialog、LxDrawer、LxEmpty、LxPageCard、LxFormErrorBanner

## 评审范围与证据

评审对象为五个组件、对应 Demo 和 `linkx-fe/docs/components/` 文档页，并对照 `doc/lx-ui/DESIGN-SPEC.md`、`doc/lx-ui/COMPONENT-STYLE-INTERACTION.md` 及主题令牌。独立浏览器检查了文档页的桌面/375px视图、亮色与 HUD 切换、Dialog 和 Drawer 打开、表单校验与提交 loading、PageCard loading/error、Empty 创建/清筛选操作和 ErrorBanner 字段说明展开。

浏览器证据：Dialog 在 375px 下为 343px 宽，单列字段，按钮 44px 高，无页面横向溢出；Drawer 在 375px 下铺满视口，内容行与底栏按钮可见；PageCard 和文档的主要正文在窄屏可读，但 PageCard API 表格内部内容宽于视口约 7px。HUD 切换后 Dialog、Drawer 的示例宿主变深色，而 `append-to-body` 挂载到 body 的浮层仍为白色。Reduced-motion 通过源码核对：`variables.css` 有全局 `prefers-reduced-motion` 降低动画/过渡时长的规则；本次未在浏览器模拟该系统偏好。

## Design-specificity verdict

**总体判断：中上，设计语言已有 LinkX 产品脉络，但浮层主题切换脱离了产品主题，错误恢复演示也尚未兑现文案承诺。** 组件以 LinkX 的紧凑控件、警务/审计数据情境、业务术语、受控插槽和语义令牌组织界面，明显不是通用后台套壳。Dialog 的三段分区、危险操作红色强调、Drawer 审计明细和 Empty 的“新建/清除筛选”情境都和 LinkX 使用任务吻合。主要机会是让 Teleport/append-to-body 后的浮层继续继承 HUD 主题，并收拢演示中的反馈与恢复路径。

## 整体印象

页面结构清楚，弹窗表单、详情抽屉、列表空态和表单阻断各自承担明确职责。桌面界面克制而紧凑，375px 下主要操作仍能到达。几个明显断点集中在跨到 body 的浮层、抽屉键盘关闭默认行为，以及 PageCard 错误态里“请重试”与实际按钮行为不一致。

## 认知负荷清单

- 单一焦点：通过。各示例的组件意图清楚；Dialog 的双列数据分组在移动端收为单列。
- 信息分组（每组不超过 4 项）：通过。表单字段、详情行和错误说明分组明确。
- 相关信息视觉归组：通过。标题、主体、footer 之间有稳定边界。
- 视觉层级：通过。主标题、组件示例、操作按钮和错误信息易区分。
- 一次处理一个决定：通过。Dialog 主次操作有清晰层级；Empty 只在对应空态出现恢复/创建动作。
- 选项数量（每个决策点不超过 4 项）：**失败 1 项**。PageCard Demo 同时露出“加载遮罩、显示边框、内容内边距、展示错误态、HUD 深色主题”五个开关；评审者需要把它们当作配置面板，而不是沿着一个状态逐步理解组件。
- 工作记忆：通过。组件文案解释了受控状态与宿主责任，任务信息都留在当前区域。
- 渐进披露：通过。API 和代码样例折叠，细节不会一开始铺满页面。

判定：**低到中等负荷，8 项中 1 项失败**。五个并列开关是主要额外负担；文档侧栏的大量组件属于整库文档导航背景，不归因到这五个组件本身。

## 情绪旅程

1. **进入任务：放心。** 标题与表单用途明确，默认取消/确认顺序符合后台惯例。
2. **填写与查阅：稳定。** 标签-值行与字段分区易扫读；移动端字段变单列，抽屉底栏仍保持可达。
3. **提交遇到阻断：短暂不确定。** Dialog toast 会告诉用户要填写地点，但消息短暂且不附着在字段或横幅上；HUD 场景下 toast/弹窗还有主题断层。
4. **尝试恢复：不够确定。** PageCard 的提示建议重试，点击刷新却不改变错误态；Drawer 只靠手动定位关闭按钮，键盘用户缺少预期快捷路径。
5. **结束任务：通常顺畅。** 成功提示可确认结果，危险确认清楚描述后果；但示例环境的本地反馈不完全等同真实恢复。

## 强项

1. **组件分工和业务语义可信。** 表单用 Dialog、审计详情用 Drawer、全局规则阻断用 ErrorBanner、无记录时由 Empty 给下一步，清楚解释何时选哪个容器。
2. **移动端核心交互保持完整。** Dialog 375px 截图显示单列字段、44px 关闭区和按钮；Drawer footer 将操作纵向放置，没有页面横向滚动。
3. **状态说明和视觉语义基本闭环。** PageCard 保留内容并标出忙碌状态，ErrorBanner 使用专属表单错误令牌，危险操作同时改标题、图标和确认按钮，避免只靠颜色传意。

## 优先问题

### [P1] HUD 主题没有穿过 Dialog/Drawer 的 portal

**证据：** 两个 Demo 都把 `lx-theme-hud` 加在局部 section；组件使用 Element Plus 的 `append-to-body`，实际 `.el-dialog`/`.el-drawer` 位于 body 下，切换后宿主变深而浮层仍是白卡。亮色下看不出问题，深色时会像浮层突然脱离当前产品。

**影响：** 深色大屏用户会遇到强烈闪白感和主题断裂，尤其是夜间审计/确认操作；当前 Demo 声称支持 HUD，但没有展示真实主题结果。

**修复方向：** 让主题状态覆盖 portal 根节点（例如由宿主把主题类放在 body/app 根，或用共享主题状态同步 portal 容器）；补上 Dialog 与 Drawer 实际打开时的亮/HUD 对照。

**建议命令：** `/impeccable polish`。

### [P1] Drawer 默认关闭 ESC，和库内键盘规范冲突

**证据：** `LxDrawer` 默认 `closeOnPressEsc: false`；`doc/lx-ui/DESIGN-SPEC.md` §9 要求“抽屉 Esc 关闭”。详情抽屉虽然有 44px 的关闭按钮，但它不是键盘用户的快速退出键。

**影响：** Alex/Sam 在打开详情后无法按常规方式退出；当抽屉含多个可聚焦元素时，需完整 Tab 到关闭按钮，降低用户控制感并延长返回路径。

**修复方向：** 默认遵循 Escape 关闭；仅在确有未保存表单的场景由宿主显式关闭 ESC，且给出未保存离开确认。

**建议命令：** `/impeccable harden`。

### [P2] Dialog 校验错误只用短 toast 表达

**证据：** 空地点提交时只出现“请填写案发精确地点”的全局短 toast；字段自身没有错误边框、提示文本或错误横幅，焦点也留在确认按钮。

**影响：** 用户看到位置提示后，需要自己从按钮跳回字段并判断何时错误已修正。消息消失后，错误无法在再次提交前持续识别；读屏用户也缺少与字段关联的错误关系。

**修复方向：** 将错误持久显示在具体字段旁，关联 `aria-describedby`/`aria-invalid`，提交失败后把焦点移到第一个错误字段；全局提示可作补充，不作唯一反馈。

**建议命令：** `/impeccable clarify`。

### [P2] PageCard 错误 Demo 的“重试”并不恢复

**证据：** 错误文案写“请检查网络后重试”，但“刷新概况”只更新页面底部的本地状态文字；勾选错误态时错误始终保留，没有重试中或恢复成功状态。

**影响：** Demo 教给调用者一个不成立的恢复路径，也让用户无法判断组件 loading/error 由谁持有、怎样回到成功状态。

**修复方向：** 让“刷新概况”清除错误并短暂展示 loading 后恢复样例数据，或把错误文案改成纯状态展示并移除“重试”暗示。

**建议命令：** `/impeccable harden`。

### [P2] 文档 API 表在 375px 下压缩到逐字换行

**证据：** PageCard API 表格有一列内容宽于 327px 可视区约 7px；LxEmpty props 表因列数多而出现窄列长值逐字换行。正文页面本身没有整体横向溢出，但表格读起来费力。

**影响：** 移动端查阅者难以快速对应属性、类型和说明，降低组件文档的可用性。

**修复方向：** 为 API 表格提供自身容器横向滚动、卡片式窄屏布局或分拆字段说明，避免把页面宽度压成狭窄列。

**建议命令：** `/impeccable adapt`。

## Persona 红旗

- **Sam（键盘/读屏依赖用户）：** LxDrawer 默认不响应 Escape，与全库键盘要求冲突；Dialog 的示例错误未在字段附近留下关联错误，读屏用户只会听到短暂 toast。HUD 浮层仍为白色，也使深色主题一致性不足。
- **Alex（熟练用户）：** 每次打开详情都需找到关闭按钮，缺少标准 Escape 退出；PageCard 状态 Demo 用五个平级开关表达状态组合，检查组件行为比必要的更费时。
- **Riley（边界测试者）：** PageCard 错误态宣称可重试，但点击刷新不会清除错误；Drawer Demo 的录像文件名蓝色下划线且有 `cursor: pointer`，实现却是 `span`，造成不可操作链接的假象。

## 次要观察

- ErrorBanner 的标题 12px、描述 11px；颜色有错误语义且在截图中可辨，但长时阅读仍偏小。
- LxPageCard loading 遮罩保留内容结构，加载图标可见；最好补一句状态文案，避免长等待时 spinner 无上下文。
- Dialog 与 Drawer 关闭按钮视觉图标清楚、44px 目标符合触控要求；键盘焦点环在源码中明确存在。
- LxEmpty 的默认线稿和操作按钮留白适中，长描述在 375px 下能换行；业务说明也明确区分空、加载和错误，避免把失败伪装成空列表。
- 本次 Assessment A 未运行 detector，也未检查 overlay；这是为保持 Assessment A/B 隔离而刻意保留的边界。未检查系统 reduced-motion 实际浏览器渲染，仅确认全局 CSS 规则存在。
