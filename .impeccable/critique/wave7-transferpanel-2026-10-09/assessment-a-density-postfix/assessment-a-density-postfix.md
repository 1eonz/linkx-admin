# LxTransferPanel 窄屏密度复验：Assessment A

## 范围与结论

- 目标：`http://127.0.0.1:4174/components/lxtransferpanel`
- 评估方式：独立设计与交互评估；使用隔离的 Chrome 页面，分别设为 320×844 与 390×844 CSS px。未读取或使用 Assessment B 的 detector 结果。
- 范围：右侧已选长名称折叠高度与全文可见性、summary 点击/Enter/Space、已选列表滚动边界的移除按钮、与 `design/虚拟滚动树 + 双栏穿梭/screen.png` 对照。
- 源码一致性：四个目标文件的采集前后 SHA-256 全部一致，详见 [source-hashes.json](./source-hashes.json)。

**设计特异性：高。**“待选/已选”、资源编码、在线状态、未加载历史授权和下级继承等信息明确服务于权限分配场景，结构和用词并非可直接套用到任意列表的通用展示。设计图采用双栏桌面布局；当前窄屏切为两个 44px 高的面板切换按钮，属于合理的触屏适配。

当前改动使超长名称在折叠态限制为两行，也能以三种输入方式打开全文。主要剩余问题集中在 320px 下展开条目过高后滚动到底的裁切，以及未加载条目折叠态仍偏高。

## 实测结果

| 状态 | 320px | 390px |
|---|---:|---:|
| 页面横向溢出 | 无，scrollWidth 320 | 无，scrollWidth 390 |
| 折叠长名称可见 | 2 行，34px；行高 16.8px | 2 行，34px；行高 16.8px |
| 折叠的未加载条目总高 | 99.59px | 99.59px |
| 展开条目总高 | 186.17px | 152.58px |
| 全文高度 | 100.78px | 67.19px |
| 点击 / Enter / Space 展开全文 | 全部通过 | 全部通过 |
| 展开后滚到列表底部 | 全文开头及移除按钮中心被裁切 | 全文完整，移除按钮中心仍可命中 |

“完整名称”是 Demo 中 80 字的未加载历史授权项。折叠态名称自身限制为两行；约 100px 的条目高度还包含 `LEGACY-08`、停用状态、未加载提示和节点键值等元数据。展开后，320px 的全文区域在触发自动滚动时可以完整进入列表视口；继续滚到精确底部时，全文上沿位于列表上沿之外 16.22px，首行不可见。此时 44×44px 移除按钮中心位于列表上沿之外 13.61px，中心点命中测试未命中按钮。390px 下全文与按钮仍在可视区域内。

320px 下 summary 展开后的自动滚动位置也把 summary 顶边推到列表裁切线上方 4.61px；390px 下高出 1.61px。全文可见，但焦点描边的上沿部分被裁切。

设计参考中的桌面右栏以短名称、行内编码和右侧移除图标呈现 5 个项目，列表密度明显高于窄屏的未加载历史项。当前移动端的分栏切换和 44px 控件提升了触屏可操作性；但 320px 下 99.59px 的折叠条目仍占列表视口的大部分，展开后达到 186.17px，不能仅凭桌面参考判断长文本状态已达到同等密度。

## Nielsen 启发式评分

| 启发式 | 分数 | 依据 |
|---|---:|---|
| 1. 系统状态可见性 | 3/4 | 已选数量、节点状态和列表剩余项提示可见；长名称的展开状态也能由 `aria-expanded` 表达。 |
| 2. 与真实世界匹配 | 4/4 | “权限”“未加载”“继承”等词和编码、状态符合资源授权流程。 |
| 3. 用户控制与自由 | 3/4 | 可单项移除、批量清空、筛选和展开；320px 展开到底时移除按钮中心不可命中。 |
| 4. 一致性与标准 | 3/4 | 使用统一的状态和操作模式；长名称详情的滚动边界在 320px 与 390px 表现不同。 |
| 5. 错误预防 | 3/4 | 未加载状态和危险清空确认降低误操作；窄屏底部的移除控件裁切会增加操作不确定性。 |
| 6. 识别而非回忆 | 3/4 | 编码、状态和完整名称可以查看；折叠时用户仍需主动展开长名称。 |
| 7. 灵活性与效率 | 3/4 | 有列表搜索、批量动作、移动面板切换和键盘展开；长条目占用滚动空间。 |
| 8. 美观与简约 | 2/4 | 桌面参考紧凑；窄屏的未加载长条目折叠约 100px、展开约 186px，信息块显著压过相邻条目。 |
| 9. 错误识别与恢复 | 3/4 | 未加载项目显示状态与键值；移除按钮被裁切时需要先反向滚动才能恢复操作。 |
| 10. 帮助与文档 | 3/4 | 控件有明确名称，组件文档说明可展开完整名称及状态语义；可进一步说明移动端滚动边界。 |

**总分：30/40。**

## 认知负荷与情绪路径

移动端分栏切换只有两个选项；单次可见的已选行少于四项，没有超过四个可选项同时争夺注意。搜索、批量操作、计数和继承开关让当前选择状态容易识别。长名称的“查看/收起完整名称”语义和方向图标提示了可展开性，键盘路径也能正常完成。

清晰的项目状态和计数为授权操作提供了基本把握感。遇到长历史记录时，展开能看到完整文本；320px 用户继续滚到列表底部后，文本首行和移除操作同时离开裁切范围，造成“信息还在但当前无法确认/移除”的短暂落差。对权限清单来说，这应作为移动端边界问题处理。

## 优点

- 权限领域信息具体：已加载状态、历史未加载状态、资源编码和继承选项各自清楚。
- 原生 `<details>/<summary>` 支持点击与键盘操作；本轮实测 320px、390px 的点击、Enter、Space 均可展开全文，`aria-expanded` 同步为 `true`。
- 两个目标宽度均无页面横向溢出；窄屏面板切换和移除按钮提供 44px 触控尺寸。

## 优先问题

1. **P2：320px 展开条目滚到列表底部后，全文开头和移除操作被裁切。**列表底部视口上沿为 y=404；全文上沿为 y=387.78，移除按钮中心为 y=390.39，且中心点命中测试未落在按钮上。390px 同一状态可完整阅读且按钮可命中。建议让展开条目滚动到边界时同时保留名称首行与移除目标，复验 320px 底部边界。
2. **P2：折叠态长历史项仍占约 100px。**长名称自身只有 34px、两行，但未加载项的编码、状态、提示和键值把整行撑到 99.59px；相较普通短条目明显加重右栏的垂直密度。可评估将辅助元数据归并为更紧凑的次级行，同时保留未加载标识与键值可查性。
3. **P3：自动展开后的 summary 焦点描边上沿部分被列表裁切。**320px 下 summary 顶边超出列表 4.61px，390px 下超出 1.61px。建议滚动定位时以 summary 与全文整体作为可见目标，避免键盘焦点提示贴着裁切线。

## 用户类型风险

- 移动端单手操作的管理员：320px 展开后滚到底，移除按钮中心消失，需要回滚才能操作。
- 核对历史授权的管理员：折叠态清楚显示两行名称，但整行仍被多项元数据拉高；展开后滚到底可能看不到名称首行。
- 键盘用户：Enter 和 Space 能展开，符合预期；summary 上沿的焦点描边裁切会削弱焦点位置反馈。

## 次要观察

浏览器控制台记录到一条未带请求 URL 的 404 资源错误；页面可正常渲染，无法据此归属到穿梭面板，本评估不将其计为组件缺陷。

## 需要产品决定的问题

- 在 320px 上，未加载历史项的编码、状态和节点键值是否都必须常驻显示？若必须显示，是否接受它比普通条目高约两倍？
- 展开长名称后，用户滚到列表末尾时，名称首行和移除按钮应优先固定可见，还是允许用户在“读详情”和“操作条目”之间短距离回滚？
