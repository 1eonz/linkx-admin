- 目标页面：`http://127.0.0.1:4174/components/lxtransferpanel`

## 设计特异性

**判断：高，具有明确的数据权限与组织管理语境。** 左侧组织树、右侧已选权限清单、组织编码、在线状态、继承授权和选择上限共同指向警务组织权限分配；状态与数量也通过文字呈现，不依赖颜色单独传达。页面不是可直接套用到任意列表的普通穿梭框。

设计参考 `design/虚拟滚动树 + 双栏穿梭/code.html` 将桌面两侧面板定为 `380px`（第 406、511 行）。当前文档 Demo 主动采用 `300px`，组件 API 仍默认 `380px`。这一差异有文档说明，是针对示例页纵向占用的局部调整，不是组件默认契约变更。

## 整体印象

桌面 Demo 默认从 `380px` 降到 `300px`，现场测得两个面板均为 `325×300px`，确实少了 `80px`（约 `21%`），用户指出的文档页外框过高问题在桌面得到实质改善。窄屏实际值受 `352px` 最小高度约束，因此不会按 `300px` 显示；桌面缩短面板也会同步减少树列表可见行数。整体处理方向正确，仍需区分“外框占用”与“面板内容密度”。

这里的“选择框过大”按两侧待选/已选面板理解。若反馈指的是方形复选框本身，源码中复选框图形为 `14×14px`，移动触控区域扩展为 `44×44px`；本次浏览器检查中图形尺寸没有显示过大的迹象，触控区属于不可见的可操作范围。

## 有效设计

- **权限对象关系清楚。** 待选树与已选清单并排，编码、状态、数量和继承选项帮助操作者交叉核对目标。
- **桌面占用有明确改善。** `300px` 默认档让预览矮了 `80px`，而 `240px` 与 `380px` 仍可手动比较；API 标准高度没有被 Demo 调整误改。
- **窄屏仍可完成主操作。** `390px` 下切换待选/已选面板，文档宽度保持 `390px`；复选框与展开控件保留 `44px` 触控区。

## 优先问题

### [P2] 窄屏的 300px 配置仍呈现为 352px

**观察：** `390px` 视口下默认面板实测为 `352px`，树视口高 `129px`。这是 `index.vue` 的窄屏最小高度规则覆盖了 Demo 的 `300px` 值；320px 下也保持该下限。相较原先 `380px`，窄屏只减少 `28px`，不是桌面减少的 `80px`。

**影响：** 如果用户在手机上也认为面板过高，当前默认档不能提供同等程度的缩小；但 64px 树行和 44px 触控区也限制了可压缩空间。

**建议：** 明确这次目标是桌面文档预览还是所有窄屏面板。若需压缩窄屏，优先减少非操作性纵向留白，并保留 64px 树行及 44px 触控区；不要仅把高度值强压到 300px 后裁切可操作内容。

### [P2] 缩小外框同时显著减少可见树行

**观察：** 桌面 `300px` 面板的树视口实测高 `125px`，约可显示 4 行 32px 树项；切到 `380px` 后树视口高 `205px`，约可显示 6 行。`240px` 档的树视口只有 `65px`，接近 2 行。当前桌面标题与操作区高 `95px`，占 300px 面板约三分之一。

**影响：** 外框更短了，但 1,420 个组织节点中可见的上下文也变少；操作者需要更频繁滚动，较长标题/批量操作还会增加表头高度。继续降低到 240px 会让树视口过于狭窄。

**建议：** 保留 `300px` 作为桌面紧凑 Demo 档，先收紧标题/次要操作所占高度，或将低频筛选批量动作进一步折叠；评估时同时看面板外框和树视口可见行数，避免用过低高度掩盖内部空间分配问题。

### [P3] 默认高度控制藏在未说明高度的折叠组中

**观察：** 初始页面只显示“示例状态与主题”；“面板高度”选择器要展开后才可见。用户需要主动猜测设置入口，才能比较 240、300 和 380px。

**影响：** Demo 默认值虽已改变，但用户不容易发现可调整档位，也难区分紧凑示例和组件 API 默认高度。

**建议：** 将折叠组名称改为包含“面板高度”的具体描述，或在可见摘要旁标明“当前 300px”；继续在属性文档说明 API 默认仍为 380px。

## 认知负荷

- 主任务与两栏关系明确；关键对象名称、编码、状态和当前数量可直接识别，无需记住前一步的信息。
- 桌面主要路径有勾选、全量加入/移除和清空；筛选后的批量动作按需出现，没有在初始画面同时堆出过多操作。
- 首屏不显示 240/300/380 档位、主题或加载状态；它们位于折叠控制内，属于轻度可发现性成本。
- 300px 高度使桌面树可视行数从标准档约 6 行降至约 4 行。该变化是更紧凑布局带来的操作成本，不是新的步骤数。
- 未发现初始页面横向溢出；在 320px 展开 Demo 设置时，文档宽度仍为 320px，代码片段内部横向滚动不扩展页面宽度。

## 情绪旅程

页面先以已选数量和状态文案提供确定感；操作者勾选后可在右栏复核对象及编码，减少权限错配的担忧。达到上限时显示剩余名额，清空前确认，并在 Demo 中提供撤销，这些反馈有助于高影响操作的安全感。体验低点是窄屏面板仍占 352px，且 64px 树行下每屏约看到两行，连续查找较多组织时会增加滚动负担。错误态保留当前选择并提供重试，结束点较可靠。
