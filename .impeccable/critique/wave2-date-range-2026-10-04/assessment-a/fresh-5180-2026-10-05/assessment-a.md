# LxDatePicker Assessment A：纯设计评审

Method: isolated Assessment A (design review with a fresh browser tab; no Assessment B or detector evidence used)

目标：`http://127.0.0.1:5180/components/lxdatepicker`  
评审日期：2026-10-05  
模式：Operate / Read；以日期区间完成任务为主，文档演示页为承载面。

## 设计特异性

**结论：组件层中高，文档外壳较通用。** 组件并非直接套用任意日期控件：现场触发器为 32px 高、4px 圆角，图标和焦点沿用 Lx 色彩令牌；中文「至」、周一起始、连续区间带和面向布控、研判的字段语境，都与 `design/表单控件八件套/code.html` 的日期范围标本相符。桌面双月、窄屏单月也保留了同一交互语言。Element Plus 的日历网格仍是熟悉的类别模式，页面导航外壳则是常规组件文档布局，这与工具型组件页相称。

现场实测 CSS 已加载：默认日期区间触发器计算样式为 `border-radius: 4px`、`height: 32px`、内描边；激活时主色边线和焦点光环出现。HUD 开关将 demo 区域切为深色，弹层背景实测 `rgb(22, 35, 58)`，输入表面为 `rgb(16, 26, 44)`，说明通过附加类切换的触发器和弹层主题都生效。

## 认知负荷

八项检查中有两项在部分状态失败，整体为**中等负荷**。分组、标签和标题层级清晰，区间两端同时可见；扩展参数采用折叠，降低了低频信息的干扰。主要负荷来自日期网格一次显示 35–42 个日期选项，这是日历任务的固有复杂度，连续选区和周表头能帮助定位。短视口中，指针位于弹层时滚轮滚动的是文档，弹层仍可能被视口裁切，打断了「只处理当前日期选择」的注意焦点。

| 检查项 | 结果 | 依据 |
|---|---|---|
| 单一焦点 | 部分失败 | 正常高度下日期面板聚焦于选区；短屏滚轮会带动整页。 |
| 分块（每组不超过 4 项） | 通过 | 示例按日期区间、单日/月、快捷范围等分组。 |
| 相关项分组 | 通过 | 标签、触发器、提示和状态处于同一示例区块。 |
| 视觉层级 | 通过 | 页面标题、示例标题、字段标签和帮助文案层级明确。 |
| 一次做一项决定 | 通过 | 打开弹层后，用户可先定位月份再选择日期。 |
| 最少选择（每个决策点不超过 4 个可见选项） | 失败 | 月历同屏展示大量日期格；这是任务本身的选项量。 |
| 工作记忆 | 通过 | 两个端点与所选区间持续留在触发器和日历上。 |
| 渐进披露 | 通过 | 低频参数折叠；组件示例有标题分区。 |

## 情绪旅程

进入页面先看到组件名和短说明，随后看到有真实值的区间输入，减少空状态的不确定感。展开后，桌面双月网格和连续选区带构成清晰的任务峰值；当前值仍留在输入框，降低选择过程中的记忆负担。HUD 主题能立即展示令牌映射后的深色效果。情绪低谷出现在 390×375：日历面板底部超出视口，滚轮却移动整页，弹层随触发器重新定位后仍被裁切，用户难以确认最后一行是否可达。文档没有给这种窄高度状态明确的结束或恢复提示。

## 做得好的地方

1. **所选范围易读。** 起止日期以主色圆点突出，中间日期形成连续浅色带；两个端点仍显示在输入触发器内，能相互校验。
2. **业务语境贴合控件。** 32px 基线、4px 圆角、中文分隔符和周一开周与设计标本一致，未把通用英文默认值留在页面上。
3. **主题切换有实际覆盖。** HUD 状态不仅改变 demo 卡片，也通过弹层附加类改变 teleported 面板背景和输入表面，视觉反馈即时。

## 优先问题

### [P2] 390×375 短屏下日历底部裁切，滚轮由页面接收

**影响：** 单面板高 363px，顶部位于 y=28，底部到 y=391，超出 375px 视口 16px。面板和子元素没有可滚动区域；在弹层中部滚轮后 `window.scrollY` 从 118 增至 493，页面根滚动区接收了滚动，弹层重新锚定后底部仍到 y=449。短屏用户可能看不到末行，也无法从弹层本身滚动。375×812 时面板完整可见。  
**建议：** 针对可用高度限制弹层高度并让日期主体内部滚动，或采用能保持选区可见的短屏布局；验证输入焦点与弹层锚点在页面滚动后的关系。  
**建议命令：** `/impeccable adapt`

### [P3] 演示没有给出错误态的视觉样例

**影响：** 基础示例展示禁用和只读，但不展示 LxForm 校验上下文中的红边、错误底色及邻近错误文字。使用者需依赖文字契约来判断控件在表单出错时的实际层级和对比。  
**建议：** 补一组静态或可切换的表单错误样例，并保留字段错误文字，不要只展示红色边线。  
**建议命令：** `/impeccable document`

### [P3] 主示例把多段操作说明连续放在触发器下方

**影响：** 双月联动、连续色带、键盘说明和状态文案紧接在主输入后；在演示页中可用，但会拉长首组表单区块，让主要交互与解释性文字争夺注意力。  
**建议：** 保留最关键的一句键盘入口提示，把完整操作说明放入可展开帮助或就近提示；值变化状态继续通过 `aria-live` 呈现。  
**建议命令：** `/impeccable distill`

## Persona 红旗

- **Jordan，第一次使用日期控件：** 「开始日期」「结束日期」与「至」让双端含义明确；日历周一开头和快捷范围有文字说明。短屏下日历底行裁切，会让他不确定如何完成选择。
- **Sam，键盘/屏幕阅读器用户：** live AX 树将两个端点暴露为各有名称的 combobox；Escape 关闭弹层的行为已观察到。文档说明方向键/Enter 路径，但本次没有逐项验证键盘移动日期；触屏目标 44px 的实际命中范围也未在非触屏浏览器中验证。
- **Casey，单手移动用户：** 375×812 的单面板尺寸适配良好；390×375 的短高度会裁掉面板下缘，滚轮操作落到页面，且不能在日历内滚动，是主要红旗。
