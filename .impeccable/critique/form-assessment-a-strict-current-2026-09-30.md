## 做得好的地方

- 动态表单的“演示设置”使用默认关闭的 `<details>`，首次进入时不会先要求用户处理列数、禁用、主题和候选 Mock 控制。
- LxFormItem 源码使用 MutationObserver 同步必填、无效状态，并把错误 ID 加入控件的 `aria-describedby`；LxDynamicForm 校验失败后定位并聚焦首个错误字段，同时遵守减少动效偏好。
- 自适应栅格以容器宽度切换 3/2/1 列，并由 CSS 变量重算字段跨度；这在源码层面处理了容器断点与行跨度的冲突。

这些都是当前源码中的实现路径。DOM 最终属性、焦点落点、容器查询效果及读屏输出均未通过浏览器确认。

## 情绪路径

源码呈现的路径是：用户先看到表单，再按类型输入；遇到必填错误时保留字段级说明，动态表单会把视线和焦点带到首个错误；修正后可继续提交校验或重置。demo 的成功反馈表示“校验通过”，并不声称业务数据已保存，符合组件不负责请求的边界。这个路径在运行时的可见性、焦点时机和提示重复程度尚待新标签实测。

## 优先问题

1. **[P2] 上传限制没有完整转成用户可理解的说明**  
   **影响：** LxUpload 的帮助文案会显示 `image/*` 和单文件 10MB；动态示例另外配置了单张 1 个、多张 5 个的 `limit`，但界面提示不显示数量上限。用户可能在添加文件时才发现数量限制，也不一定知道具体允许的图片格式。  
   **建议：** 对用户显示可识别的格式名称、单文件大小和文件数量上限；如果限制来自 schema，考虑由控件从 `accept`、`maxSize`、`limit` 生成一致的提示。  
   **建议命令：** `/impeccable clarify`

2. **[P3] Vue 文档仍用 React 命名引入受控值契约**  
   **影响：** 动态表单文档称 `value + change(nextValue)` 是 React 常见命名，随后才解释它仍是 Vue 契约且无需 React runtime。说明是完整的，但 Vue 使用者可能先停下来判断该 API 是否适用于当前项目。  
   **建议：** 以“受控值用法”作为主称呼，并把 Vue 模板示例放在首次说明处；保留 React 命名来源作为补充背景即可。  
   **建议命令：** `/impeccable clarify`

3. **[P3，待验证，不作为已确认缺陷] 错误态的图标位置与可读性需要实屏核对**  
   **影响：** 当前样式把 12px 圆形感叹图标放在错误文案前，文字为设计稿规定的 11px。仅凭源码无法确认设计稿中输入框尾部的错误标识是否也应出现，也无法判断不同主题和缩放下的对比度及可读性。  
   **建议：** 在可用浏览器中分别采集桌面、窄屏、错误态和 HUD 主题；比对设计稿图标位置，并测量文字对比度、检查 200% 缩放，再决定是否需要改动。当前不建议因旧尺寸偏好直接偏离 11px 设计值。  
   **建议命令：** `/impeccable audit`
