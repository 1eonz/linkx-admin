## 设计特异性判断

这是为 LinkX 权限和组织管理场景定制的界面，不是可替换到任意后台的通用穿梭框。组织树、部门编码、状态语义、未加载历史授权、继承说明、`5:2:5` 双栏比例和 HUD 深色预览共同形成产品性格。亮色面板采用浅灰表头、紧凑 32px 行高和单一业务主蓝；HUD 预览切换到深空底与 sky 主色，且只作用于组件预览，符合文档中“外壳保持比较基准”的约定。

本次没有运行静态 detector，也没有取得 Assessment B 结果，因此不存在自动规则命中数量、文件位置或 overlay 结论可供合并。浏览器手工证据显示页面无 `pageerror`，响应监听未记录 HTTP 4xx/5xx；控制台出现一条未带 URL 的通用 404 资源提示，应在 B 阶段确认其来源，不能在本 A 阶段把它判定为组件缺陷。

## 整体印象

修后版本把高风险的树选择、筛选、窄屏触控和长名称处理都收进了一个可解释的交互模型。桌面上读数紧凑，窄屏则用“待选/已选”切换、64px 两行树行和 44px 目标维持可操作性；长名称展开后会把列表滚动到可读位置，移除按钮仍固定在触控列。最大机会是处理“固定行高与可读插槽内容”的张力，并让 Demo 打开全部边界控制时仍保持单一主线。

## 做得好的地方

1. **状态反馈和风险护栏成体系。** 树筛选显示“筛选匹配到 12 个节点；路径祖先不计入数量”，勾选后反馈新增数量与总数；TransferPanel 对上限、未加载授权和危险清空给出不同层次的解释，避免把“当前树节点总数”误读成“可加入数量”。
2. **窄屏布局是结构化适配。** 375px 下切换条为两列，树行稳定为 64px，展开和复选外层均为 44×44px，文档正文和组件没有横向溢出（`documentScrollWidth = 375`）。选中列表有滚动提示，隐藏面板从焦点和辅助技术路径中移除。
3. **长名称与键盘焦点处理可信。** 375px 下长名称先折叠，Enter 展开后条目高度约 140.6px、列表自动滚动到 `scrollTop = 175`，移除按钮仍为 44×44px；Space 再次操作收起。树方向键操作后焦点仍落在正确的 `treeitem`，而不是退回文档。

## 优先问题

### [P1] 自定义树节点插槽在窄屏会被固定行高裁切

**为什么重要：** `LxVirtualTree` 的 stacked 行把 `node-extra` 固定为 16px 高并隐藏溢出（`index.vue:1234-1243`），Demo 的压力插槽同时放入两行说明（`demo/basic.vue:254-261`）。375px HUD 截图中，插槽文字在标签右侧变成细小、被截断的两行，读者无法确认完整状态；这会让宿主误以为“已渲染”而实际丢失信息。

**修复方向：** 把 stacked 插槽契约收窄为单行元数据（超长内容进入 `nodeSummary`/可访问摘要），或为非空插槽提供明确的截断标记和可键盘触发的全文查看入口；不要把任意块级、多行内容直接塞进 16px 槽位。为代码、状态这类标准元数据保留当前两行布局。

**建议命令：** `/impeccable harden`

### [P2] 240px 默认高度在窄屏给选中列表留下很小的首屏窗口

**为什么重要：** 375px 下 TransferPanel 实际高度为 352px，但头部、筛选、页脚和继承说明占用后，选中列表可视高度约 136px，4 项初始选择只显示 2 项，长历史授权必须依赖滚动提示才能发现。滚动提示确实存在，但权限核对场景中“已选内容”是核心结果，首屏只露一半会增加来回滚动。

**修复方向：** 窄屏默认把 `panelHeight` 提升到能显示至少 3 条短项，或将继承说明折叠为可展开辅助说明；保留当前列表内滚动和“下方还有 N 项”提示，避免把面板扩成无限高度。

**建议命令：** `/impeccable layout`

### [P2] 批量操作的主次关系在窄屏不够明确

**为什么重要：** 中间“全部加入/全部移除”使用图标按钮、按钮下标签和名额提示三层信息。375px 截图中“全部加入”因上限禁用，但灰色箭头与“需加入 2 项；仅剩 1 个名额”分散在两行；“全部移除”则以蓝色实底突出。熟悉穿梭框的人可以推断，首次使用者仍需把图标、颜色、标签和上限文案拼起来判断下一步。

**修复方向：** 保留 44px 图标触控区，但把可执行状态、上限原因和动作标签组合成稳定的两列块；禁用时将原因紧邻按钮并降低非动作装饰权重。桌面可以恢复更紧凑布局，窄屏使用两列等宽操作卡。

**建议命令：** `/impeccable clarify`

### [P2] Demo 展开全部边界设置后形成“控制墙”

**为什么重要：** VirtualTree 的状态按钮、数据操作三组和边界与外观三组，在全部展开时同时出现超过 10 个动作；TransferPanel 的 Demo 还把 4 个宿主状态、3 个参数开关、面板高度选择和状态反馈放在组件前方。组件功能本身没有被阻塞，但第一次阅读文档的人会先处理 Demo 控件，而不是理解树/穿梭组件的核心行为。

**修复方向：** 默认只显示一个主状态选择和一个“显示边界案例”入口；把 HUD、插槽压力、上限和继承说明归入同一“边界案例”区域，并让当前激活案例在组件旁显示短状态标签。

**建议命令：** `/impeccable distill`

## 认知负荷

按 Critique 的 8 项清单，本轮有 **3 项失败，属于中等负荷**：

| 检查项 | 结果 | 证据 |
|---|---|---|
| 单一焦点 | 失败 | Demo 展开后，多个宿主状态、主题、插槽和数据操作与组件争夺首屏注意力。 |
| 分块 | 通过 | `fieldset`、状态组、双栏面板和移动切换条提供了明确分组。 |
| 相关分组 | 通过 | 筛选、选择、展开定位、已选列表和继承说明均保持邻近。 |
| 视觉层级 | 失败 | 中间批量按钮、操作标签、上限提示和面板标题在窄屏接近同一层级。 |
| 一次一事 | 通过 | 过滤批量动作只在输入后出现，更多反选选项默认折叠。 |
| 最少选择 | 失败 | VirtualTree 高级控制打开后约 8 个动作；TransferPanel Demo 全部设置可见时超过 7 个选择。 |
| 工作记忆 | 通过 | 当前已选数、匹配数、剩余名额和未加载标记就地显示。 |
| 渐进披露 | 通过 | 状态/高级操作、反选范围、长名称全文都使用折叠或按需展开。 |

需要特别注意的决策点是：TransferPanel Demo 同时显示 4 个宿主状态按钮与 3 个参数开关；VirtualTree 的数据操作区同时显示筛选、选中、展开定位三组按钮。它们是文档演示专属负荷，若未来复用到业务页，应继续保持默认收起。

## 情绪旅程

- **进入：** 文档页面先看到“演示状态和更多操作”折叠入口，组件标题和组织树在首屏可识别，情绪是可控的探索。
- **理解：** 展开边界控制后，HUD、选中反馈和筛选计数即时变化，用户能快速确认“操作生效”，形成正向峰值。
- **压力点：** 插槽压力案例在窄屏把多行内容压到固定槽位，视觉上像信息丢失；TransferPanel 240px 窄屏首屏只能看到部分已选清单，首次核对会产生不确定感。
- **恢复：** 长名称通过 `查看全文` 展开，列表自动滚动，移除按钮不跳位；清空、错误和加载态都有确认/重试/保留选择，恢复路径明确。
- **结束：** 已选数量、滚动剩余提示、键盘说明和宿主状态文案让用户知道当前结果，收尾是可靠的；若插槽内容是业务关键字段，仍需先解决 P1 可读性。

## 小观察

- HUD 深色仅覆盖组件预览，文档外壳保持白色；这是文档明确的比较基准，但切换瞬间的白/深分界很硬，可用一条轻量预览边界或状态标签增强连续性。
- 375px 下树的标签、编码和状态没有横向溢出，`documentScrollWidth` 与 viewport 相等；这项边界处理值得保留。
- 桌面 TransferPanel 的普通选中项保持约 32px，长项自然增高到约 57.6px；长名称只有真实溢出时才增加 `details`，短名称没有额外 Tab 停靠点。
- reduced-motion context 下 `matchMedia('(prefers-reduced-motion: reduce)')` 为 `true`，组件过滤框和选中项的计算过渡时长为 `0.00001s`，符合全局降级策略；组件没有额外的循环动画。
- 浏览器控制台出现一条未带 URL 的通用 404 资源提示，但响应监听未发现 4xx/5xx，且没有 page error；应由 Assessment B 或服务日志继续定位，不能把它直接归因给目标组件。

## 修后剩余风险分级
