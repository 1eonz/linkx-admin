LxTransferPanel 双栏穿梭 ​

把虚拟树中的可选节点与受控已选列表同步展示。组件只处理展示和选择交互，不请求数据，也不判断业务权限。桌面布局固定为 5:2:5，两侧面板默认 380px 高并使用 border-box；窄屏提供待选/已选切换，一次展示一个面板并保留面板内滚动。下方文档示例的预览最大宽度为 820px 并居中，窄屏仍使用全部可用宽度；示例默认使用最紧凑的 240px 高度档，可切换到 300px 或 380px。桌面待选标题与反选入口保持同行，为树视口留出至少 120px；组件 API 默认宽度和高度契约不变。

默认样例在本地生成 1,420 个树节点，包含多层级、状态元数据和大量禁用归档项；初始预选 4 项并保留 1 个名额，便于体验新增操作，滚动只渲染可视窗口。样例不请求后端，也不代表真实接口性能验收。

const expandedGroupKeys = treeData.map((node) => node.id)
const visibleTreeData = computed(() =>
  hostState.value === 'empty' ? [] : treeData,
)
const hostStateLabel = computed(
  () =>
    ({
      ready: '正常数据',
      loading: '加载中',
      error: '加载失败',
      empty: '空结果',
    })[hostState.value],
)
watch(selectedKeys, (value, previousValue) => {
  if (value.length) {
    lastNonEmptySelection.value = [...value]
    if (undoKeys.value && value !== previousValue) undoKeys.value = null
  }
})

function setHostState(state: HostState) {
  hostState.value = state
  lastAction.value = {
    ready: '已载入组织权限数据',
    loading: '宿主正在加载组织权限数据',
    error: '组织权限数据加载失败，可重试',
    empty: '宿主返回了空树数据',
  }[state]
}

function onChange(keys: (string | number)[], nodes: LxTransferPanelNode[]) {
  lastAction.value = `选中 ${keys.length} 项；当前树中可解析 ${nodes.length} 个节点`
}

function onClearAll() {
  undoKeys.value = [...lastNonEmptySelection.value]
  lastAction.value = '已清空全部选中项，可撤销'
}

function undoClear() {
  if (!undoKeys.value) return
  selectedKeys.value = [...undoKeys.value]
  undoKeys.value = null
  lastAction.value = '已恢复清空前的选中项'
}

function onInheritChange(value: boolean) {
  inheritChild.value = value
  lastAction.value = value ? '已保留下级继承授权' : '已关闭下级继承授权'
}

Props ​

可左右滑动查看完整属性；聚焦表格后可用方向键横向浏览。

名称类型默认值说明
treeDataLxTransferPanelNode[][]左侧待选树。节点使用 id、label、children 和 disabled；可选元数据为 code、status、statusTone；节点键须唯一。
modelValue(string | number)[][]受控的已选节点键；可包含暂未加载到当前树中的既有键。
selectedItemsLxTransferPanelItem[][]当前树未加载时用于回显已选项的最近详情；只匹配 modelValue，且当前 treeData 中的节点优先。
titles[string, string]['待选资源', '已选资源']左右面板标题。
filterPlaceholders[string, string]['输入机构名称/部门编码检索...', '在已选名单中检索...']左侧筛选匹配节点名称或部门编码；右侧筛选匹配标题、编码和状态。
panelHeightnumber380面板目标高度，单位 px，向下取整且最低为 240px；非有限值回退到 380px。左侧树与右侧列表各自滚动。
defaultExpandedKeys(string | number)[][]左侧树首次展开的节点键；后续展开/收起由树组件内部管理。
maxCountnumberundefined已选键上限。超限的新增或批量加入整体拒绝；移除和清空仍可用，即使初始值已经超过上限。0 或非法非有限值表示不允许新增。

inheritChildDescriptionstringundefined建议宿主提供经业务确认的具体继承范围和关闭后的影响；说明固定显示在复选框旁并通过 aria-describedby 关联。缺失或纯空白时显示配置提示并禁用开关，组件不推断权限语义。

节点元数据 ​

LxTransferPanelNode 继承 LxVirtualTreeNode，并提供以下可选字段：

字段类型展示位置
codestring两侧节点标题后的等宽编码标签，过长时省略并保留 title 完整文本。
statusLxStatus | string两侧节点标题后的状态文本；online、processing、busy、error、offline 显示为“正常”“处理中”“忙碌”“异常”“停用”，其它值原样显示。
statusToneLxStatus | LxFeedback状态点和状态文本的语义色；不传时从 status 的标准状态值推断。

右侧已选列表优先使用当前树节点，其次使用 selectedItems 中匹配键的最近详情；无法解析时仍显示原始键，并标记“节点未加载”。对未加载项执行移除前会弹出危险确认框。懒加载宿主应把最后已知详情传入 selectedItems；旧数据若只有 ID，则按 ID 明确降级显示。

桌面短名称普通项按设计稿保持约 32px 的紧凑单行布局，名称省略显示，编码与状态和名称同行；带键盘展开入口的长名称可自然增高，未加载历史项的附加标记及原始键值另行展示，避免挤压名称。只有实际被截断的名称才提供展开入口，短名称保持静态，不增加 Tab 停靠点。聚焦长名称后可用 Enter 或空格展开完整文本，再次操作即可收起；展开时列表按条目整体边界调整滚动位置，兼顾展开入口、全文和移除按钮。320–420px 窄屏下，超过两行的已选名称默认折叠为两行，展开后全文使用条目可用宽度，编码、状态与原始键值仍可核对。筛选隐藏再恢复条目时保留其展开状态，并同步原生状态及无障碍描述。左侧页脚的“树节点总数”只显示一次，统计当前 treeData 中的全部已加载节点，包含已选和禁用节点，不等同于当前可加入数量；可加入数量与名额限制分别由操作状态和上限提示表达。

modelValue 表示宿主当前传入的受控选择，不区分草稿与服务器已保存状态。宿主必须独立展示保存中、保存成功和保存失败状态；保存失败时保留用户选择并提供重试或恢复方式，不能把本地选择变化当成保存成功。窄屏或短屏中如需增加树的可视行数，宿主可结合页面可用高度传入更大的 panelHeight；默认值仍按设计稿保持 380px，桌面组件最小面板高度为 240px，视口不宽于 767px 时实际面板高度至少为 352px，为 64px 虚拟行和窄屏触控区留出可操作空间。

选择规则 ​

操作范围 ​

操作作用范围规则
全部加入（中间向右）当前树中全部未禁用节点超过选择上限时整体拒绝，不部分加入；没有可加入节点或名额不足时按钮禁用并显示原因。
全树反选范围当前树中已加载的未禁用节点操作默认收起；入口明确标为“更多反选选项”，展开后说明筛选隐藏项的范围以及不可选项和未加载到当前组织树的已选项保持不变。
全选筛选结果左侧筛选命中的可选节点按节点名称或部门编码匹配；不可选项和仅用于显示路径的祖先行不计入操作范围。
反选筛选结果左侧筛选命中的可选节点只反转匹配节点；匹配范围外的已选状态保持不变。若操作会增加已选数量并超过上限，则拒绝。
左侧单项选择当前树中的单个节点禁用节点不能新增。
右侧单项移除当前已选列表中的单个节点可移除不可选项和未加载到当前组织树的已选项；移除未加载项前需确认。
全部移除当前已选列表清空任何非空列表前始终需要确认。

筛选与反馈 ​

  • 左侧筛选： 树标题区以“更多反选选项”显示折叠操作，无障碍名称补充说明包含筛选隐藏项；展开后显示“反选本树可选项”，并说明包含筛选隐藏项，不可选项和未加载到当前组织树的已选项保持不变。说明以锚定浮层呈现，定位在待选面板标题区内并位于筛选框与树视口之间，不改变树视口高度或覆盖筛选框；方向键提示在窄屏常驻显示，在桌面树获得焦点时显示，并通过 aria-describedby 关联到树控件。外层筛选框调用树的 filter()，按节点名称或部门编码匹配。输入非空时显示“全选筛选结果”和“反选筛选结果”，批量操作另起一行，不挤压标题；两者只操作命中且未禁用的节点，仅用于显示路径的祖先行不计入结果。筛选操作区显示匹配数量、已选状态、无可操作项或上限提示，并通过 aria-describedby 关联批量按钮。为避免重复占用树视口，内部选择说明视觉隐藏但保留 aria-live 选择状态供辅助技术播报。
  • 右侧筛选： 匹配已选项的标题、编码、原始状态值和可见状态文案。左右筛选框都有独立清除按钮；清除后焦点回到对应输入框。输入采用文本类型和搜索键盘提示，避免与浏览器原生清除符号重复。清除按钮的点击区域桌面为 32px、窄屏为 44px。
  • 选择上限： 只有会增加已选数量并使总数超过上限的操作会被拒绝，整次操作不部分写入；反选若会减少或保持已选数量仍可执行，移除和清空也不受上限阻挡，即使初始值已超限。
  • 上限提示： “全部加入”不可用时，按钮旁显示待加入数量、剩余名额或无可加入节点的简要原因；按钮的 aria-describedby 关联完整原因。筛选操作按钮也关联当前状态说明。
  • 右侧没有已选项时显示“暂无分配权限，请在左侧勾选”；筛选后无匹配项时显示“未找到匹配的已选项”。

已选列表与事件 ​

  • 右侧列表可通过键盘聚焦和滚动查看。内容未完整进入视口时，列表外的提示显示尚未完整显示的项数，并通过 aria-describedby 关联到列表；滚动到底部后提示收起。展开长名称后，组件会在列表内滚动以完整显示该名称。
  • 普通已选名称在桌面保持单行省略，只有被截断的名称才提供 Enter/空格展开入口；短名称不进入额外键盘停靠点。编码与状态同行，保持设计稿的紧凑核对节奏。未加载历史项同时展示未加载标记及原始键值；320–420px 窄屏名称超过两行时折叠，摘要末尾显示“查看全文/收起”文字入口并保留箭头，可按需展开全文。名称完整值仍保留在 title 中。展开时列表按条目整体边界调整滚动位置，移除按钮固定在条目右上触控列，不随名称换行移动；超过列表可视高度的任意长内容仍需在列表内滚动阅读，不能保证无限长度的条目同时完整可见。
  • 移除单项后，焦点移到下一项；没有下一项时移到上一项；列表清空后焦点回到列表容器。
  • change 的 nodes 只包含当前 treeData 中可解析的节点，不为未加载键构造伪造数据。需要完整业务对象时，宿主应按键从自己的数据源解析。
  • 组件没有额外 slots 或实例方法；加载、错误和重试状态由宿主包裹处理。Demo 的禁用状态只禁用操作控件并弱化这些控件，树和列表内容仍可读，状态消息显示在面板下方。
  • Demo 的 HUD 开关只作用于组件预览容器，不修改文档站外壳主题；浅色的说明文字和操作控件保持为比较基准。

窄屏交互 ​

  • 两个全量穿梭按钮的图标下方常驻显示“全部加入”和“全部移除”，与左侧的筛选结果操作区分。
  • 窄屏下切换按钮使用“待选/已选”短标签和两侧数量，完整标题仍保留在按钮无障碍名称与提示中；“待选”数量统计当前已加载树中未禁用且尚未选择的节点，选择名额另由批量操作提示说明。筛选批量操作和状态说明分行展示。待选树页脚说明方向键移动或展开、Space/Enter 选择；所有尺寸下的已选数量均保持单行。隐藏面板会从辅助技术和焦点顺序中移除；桌面缩窄到窄屏时，组件保留当前键盘焦点所在的面板。
  • 窄屏树节点名称最多显示两行，完整文本保留在标题中；编码和状态在同一行省略。320-420px 内嵌树固定使用 64px 虚拟行高，包含 44px 触控区、两行名称和单行元数据，避免视口较窄时元数据换行撑高行；复选框和展开按钮触控区均为 44×44px，复选框视觉尺寸为 14×14px，两个控件各占独立网格列；已选列表条目上下内边距为 2px，移除按钮仍保持 44×44px 触控区。已选长名称默认最多显示两行，完整名称可通过键盘或点击展开，避免长历史名称撑高条目并遮挡移除按钮。视口跨断点时树保留焦点行并重算滚动锚点。
  • 文档页仅在宽屏扩展示例正文列，并保留页面目录和全站侧栏。

继承开关 ​

inheritChildDescription 是可选展示属性。权限宿主应提供经业务确认的具体继承对象和关闭后的影响；组件不会推断实际授权范围。说明缺失或纯空白时会显示配置提示并禁用开关，说明始终邻近复选框且通过 aria-describedby 关联。Demo 可关闭“提供继承说明”检查此状态。

宿主持久化与清空确认 ​

清空动作的确认通过后，事件顺序固定为 update:modelValue([])、change([], [])、clear-all。组件对所有非空列表先显示危险确认；存在未加载节点时会明确告知无法核对节点名称。clear-all 是清空已发生后的通知，不是可取消的确认钩子。宿主仍应把组件绑定到本地草稿值，保存到后端时再提交；不要在 v-model 监听器中直接持久化每次变化。

组件只反映当前受控选择，不知道该值是否已经提交。权限宿主应显示“有未保存更改/已保存”及保存成功或失败反馈，并在失败时提供恢复草稿的路径；这些状态必须由宿主的 dirty 状态和真实保存结果驱动，不能从组件的 modelValue 推断为已保存。

未加载节点的单项移除和全部清空由组件先执行危险确认；取消时不改变受控值。确认期间如果 modelValue 的键或顺序发生变化，旧确认会失效并提示用户重新检查；仅以新数组引用传入相同键序列不会使确认失效。失效时不会清除新值或发出清空事件。宿主仍需要维护最近一次非空值，保存失败时用该快照恢复草稿；确认通过后才提交空数组。下面是接入时序示意，savePermissionKeys 由宿主提供：

ts
const draftKeys = ref<(string | number)[]>([...savedKeys.value])
const lastNonEmptyKeys = ref([...draftKeys.value])
const saving = ref(false)
let draftRevision = 0

watch(draftKeys, (keys) => {
  if (keys.length) lastNonEmptyKeys.value = [...keys]
})

function updateDraftKeys(keys: (string | number)[]) {
  if (saving.value) return
  draftRevision += 1
  draftKeys.value = [...keys]
}

function onClearAll() {
  if (saving.value) return
  const submittedKeys = [...draftKeys.value]
  const restoreKeys = [...lastNonEmptyKeys.value]
  const submittedRevision = draftRevision
  saving.value = true
  Promise.resolve()
    .then(() => savePermissionKeys(submittedKeys))
    .then(() => {
      savedKeys.value = [...submittedKeys]
    })
    .catch(() => {
      if (draftRevision === submittedRevision) {
        draftRevision += 1
        draftKeys.value = restoreKeys
      }
    })
    .finally(() => {
      saving.value = false
    })
}
vue
<div :aria-busy="saving" :inert="saving">
  <LxTransferPanel
    :model-value="draftKeys"
    @update:model-value="updateDraftKeys"
    @clear-all="onClearAll"
  />
</div>

面板应通过 :model-value 和 @update:model-value 交给草稿更新函数处理，并在保存期间用 :inert="saving" 锁定交互。这样 savePermissionKeys 只接收清空后的不可变提交快照，成功回写该快照；失败时仅在草稿版本未变化时恢复清空前快照。示例中的“撤销清空”只恢复本地选择快照，不表示已经持久化的数据也能自动撤销；服务端补偿仍由宿主按真实 API 契约实现。
