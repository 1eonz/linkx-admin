# LxCheckbox / LxRadio 独立设计评审

**评审目标：** `linkx-fe/docs/components/lxcheckbox.md` 与 `linkx-fe/docs/components/lxradio.md`，包括各自的交互 Demo。文档按 Read 模式评估，Demo 按 Operate 模式评估。

**方法与证据：** 独立阅读当前组件、样式和文档源码，并查看 `http://127.0.0.1:4174/components/lxcheckbox`、`/components/lxradio` 的 Chrome 截图。覆盖 1440px 桌面亮色与 HUD 深色、375px CSS 视口、键盘焦点、Radio 方向键选择和 `prefers-reduced-motion`。截图及采集脚本保存在本目录的 `screenshots/` 与 `browser-inspection.mjs`。

**限制：** Chrome CDP 移动模拟未生效：375px 页面仍报告 `hover:none=false`、`pointer:coarse=false`、`navigator.maxTouchPoints=0`。因此 375px 证据只用于窄视口布局，不作为真实触屏验收；脚本测到选项 32px 高也不能单独据此下触控缺陷结论。源码已定义 `@media (hover: none)` 下 44px 最小高度，但本轮未能在浏览器中验证该规则命中。未运行 detector，也未访问 Assessment B 产物。

## 设计特异性判断

这组控件不像可直接换标的通用后台样板。公共安全选项文案、浅色执勤蓝、HUD 深色主题和“白底蓝心靶环”Radio 状态共同把组件锚定在项目的业务与视觉规范里。桌面上的选中、半选、禁用状态容易区分，切换 HUD 后控件仍能与底色分离。整体结构克制，Demo、API 表格、兼容说明按阅读顺序组织。

## 整体印象

桌面体验稳健，互动示例也足够解释控件的行为；最明显的落差出现在 375px 文档阅读场景，API 表格仍按桌面列结构压缩。触屏样式有 44px 源码规则，但当前浏览器没有进入触屏媒体态，仍需真实触屏证据才能将其算作已验收。

## 做得好的地方

- Checkbox 的全选/半选和 Radio 的单选约束都用真实控件交互呈现，选中后状态摘要即时更新，示例不只是静态图。
- Demo 文案与禁用、兼容状态有业务语义，HUD 深色样式也能保留可辨识的选中、未选和禁用层级。
- 文档从交互示例进入 Props、Events、Slots 和兼容说明；Demo 代码折叠，能兼顾先体验和后查契约两种阅读目的。

## 优先问题

1. **[P2] 375px 下 API 表格难以快速扫描**：Checkbox、Radio 的多列表格被压进窄屏，长类型和说明频繁折行，阅读者需要逐行重新定位列。对经常查契约的开发者会增加定位和比对时间。建议在窄屏为表格容器提供明确的横向滚动，或将 API 行转换为按属性分块的移动布局；避免把整页撑出视口。对应证据：`screenshots/checkbox-mobile-375.png`、`screenshots/radio-mobile-375.png`。

2. **[P2，验收缺口，非已确认产品缺陷] 触屏 44px 目标尚未有运行证据**：样式源码为无悬停设备设置了 44px 最小高度，但本次 Chrome 未进入无悬停/粗指针模式。若产品需要在触屏设备上支持这些控件，应在可用的 Android/iOS 浏览器或有效设备模拟中验证整个 label 的命中框和选项间距，再记录结果。对应证据与限制见 `browser-inspection.mjs` 的两条 375px 观测。

3. **[P3] 亮色主题禁用文字视觉上偏淡**：复选 Demo 的禁用权限行在白底上与普通说明文字的对比感很弱，快速扫过时不易读出具体禁用项。可小幅加深禁用文字令牌，同时保留禁用外观；本条为视觉观察，未做颜色对比度仪器测量。对应证据：`screenshots/checkbox-desktop-light-demo.png`。

## 认知负荷

组件决策本身为低负荷：Demo 的选择组分别最多展示 4 个 Checkbox、3 个 Radio，均不超过每个决策点 4 个选项；相关选项被白色面板分组，选择与摘要同屏，不要求跨页记忆。展开源码采用按需披露。8 项清单中，组件操作未见明确失败项；文档导航链接较多但按目录分组。移动 API 表格的折行属于主要额外阅读成本，未将其误算为选项数量过多。

## 情绪旅程

读者进入页面后先看到组件名称、用途与业务样例，接着可直接点选并观察即时状态，减少“操作是否生效”的不确定感。禁用项和半选项展示出边界状态；Radio 的旧 `label` 兼容示例收束了迁移顾虑。整个 Demo 是本地内存交互，页面也明确说明这一点，因此不会让人误以为真实权限已经写入。结束时可继续查契约或转到相邻组件；移动表格是旅程中最明显的摩擦点。

## Persona 红旗

- **Alex（熟练用户）**：Radio 方向键可在组内移动并切换选项，减少鼠标依赖。Checkbox 多项仍需逐个操作，但这是基础控件示例；本目标没有批量授权工作流，不能据此判断生产页效率。
- **Sam（键盘/辅助技术用户）**：截图与脚本确认 Radio 可由 Tab 进入、显示 `focus-visible` 焦点环，方向键能切换；Checkbox 也有可见焦点光环。组标签和原生控件语义有源码依据。屏幕阅读器播报未在本轮实测，故不把源码说明当成 SR 验收结论。
- **Casey（移动用户）**：375px 窄屏没有页面横向溢出，Demo 面板能纵向阅读；触控目标是否达到 44px 仍因设备模拟失败而未验证，移动表格也显著更难扫读。

## 次要观察

- 减少动效媒体查询命中时，Radio 靶心过渡从 0.15s 缩至 `1e-05s`，视觉上关闭缩放动画。
- 键盘焦点视觉形式为 Checkbox 柔和外环、Radio 实线外框；两者都可见，后续统一样式时应保留控件形状的区别。
- 本轮只有静态源码、浏览器交互和截图证据，不代表单测、Mock、组件构建或真实后端联调结果。
