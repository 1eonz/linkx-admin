# LxCheckbox 与 LxRadio 修后设计评审

方法：仅 Assessment A（独立设计评审；Assessment B 按任务范围未执行）

阶段标记：本报告是修后 A-only 评审，不代表 Impeccable 正式 Critique 已完成。未读取 baseline A 报告，也未读取任何 Assessment B 报告、截图、JSON、stderr、exit-code 或 Playwright 评审产物；未运行 detector。评审只依据当前实现、中文 API 文档、Demo 源码、设计稿 03/04 和现有测试源码。

## 评审范围与证据

- 目标实现：`linkx-fe/src/components/LxCheckbox/`、`LxCheckboxGroup/`、`LxRadio/`、`LxRadioGroup/`。

- 视觉源：`design/表单控件八件套/code.html` 的 03 单选组与 04 复选组，以及同目录 `screen.png`。
- 视角：按委派使用 Operate 模式，评估使用者能否快速读懂组件状态、完成选择并把示例映射到业务表单。
- 浏览器实页检查未能完成：首次尝试时 4174 尚不可达；主 Agent 随后启动并保持服务后，工作区 TCP 检查通过，`HEAD /components/lxcheckbox` 返回 HTTP 200。但子任务中的 CUA 新建 IAB 标签持续返回 `IAB visibility is not supported in a subagent thread`，浏览器状态只保留首次拒绝连接的错误页；可用浏览器清单没有 Chrome，命名 Chrome 会话也返回 `Browser is not available: chrome`。因此本评审无法读取两个文档页的实际截图或交互状态。评审没有启动或停止该服务。以下评分是源码、Demo 和设计稿证据下的阶段性判断，不是浏览器验收结论。

## 设计特异性

这组示例明显锚定 LinkX 的公共安全业务语境：勤务响应等级、处置通道优先级、警单流转、关联授权和支队审批都与设计稿 03/04 的样本一致。主控件沿用 Element Plus 原生选择语义，Lx 层只固化靶环、勾选状态、间距、主题和触屏尺寸；这种熟悉感符合管理系统中的 Operate 目标。组件表达具有产品语境，不是可原样换名的通用占位稿。

## 认知负荷

八项检查中有 1 项失败；整体认知负荷偏低。每个 checkbox/radio 组选项不超过 4 个，且 Demo 用标题分组，未发现单个决策点出现超过 4 个可见选项。此结论基于源码和设计稿分组，文档页当前布局无法浏览器复核。

| 检查项 | 结果 | 依据 |
|---|---|---|
| 单一焦点 | 通过 | 每段 Demo 围绕一个组件用法展开。 |
| 分块，每组不超过 4 项 | 通过 | 复选授权组为 4 项；单选水平组选项为 3 项，垂直组为 3 项。 |
| 相关内容分组 | 通过 | 水平/垂直、独立/组内用法由各自标题和面板区分。 |
| 视觉层级 | 暂定通过 | 标题、选项与说明在源码和设计稿中分层；浏览器渲染未核验。 |

## 整体印象

控件本身已覆盖常见业务表单的关键状态，且设计稿、组件样式和文档说明大体一致。最需要处理的是示例行为：Radio 的两块业务样本并非相互独立，复选状态播报又暴露内部值，开发者可能把 Demo 数据误读为真实业务标签或把联动误认为控件契约。

## 做得好的地方

- 03/04 的业务语境被直接延续到选项文字和状态；单选靶环、复选白勾/半选横杠、禁用灰阶以及 16px/8px/12px 间距均有对应实现说明。
- 实现保留原生 input 语义、组标签、方向键单选、半选 `aria-checked="mixed"`、`ElForm` 禁用继承和 44px 触屏选项高度，减少使用者对自制交互的猜测。
- 中文 API 文档不止列字段，也补充旧契约、全选/半选计算、无障碍和 Vue3 宿主用法；Demo 展示了业务状态而非纯色块。

## 优先问题

### [P1] Radio 两个示例共享 `channel` 状态

复现：打开 Radio Demo，在“垂直排布含禁用”中选中“高密加密专线”，再到“label 兼作选中值”中选“光纤骨干网”；垂直组也会切换为“光纤骨干网”。原因是 `basic.vue` 第 12 行定义单个 `channel`，而第 74、91 行两个组都绑定它。

影响：两个独立展示的 API 示例发生隐式联动，用户可能误以为 `LxRadioGroup` 会跨组同步，或怀疑选中状态不稳定。

建议：给旧 `label` 契约示例分配独立的 `legacyChannel`，并让每组状态摘要明确对应的组选项。此改动保持 03 样本内容不变。

### [P2] 复选状态播报输出内部值

复现：在 Checkbox Demo 保持初始状态或切换“关联授权业务权限”“通知渠道”选项，查看底部 `aria-live` 摘要；它会播报 `video`、`briefing` 等值，而不是“视频巡查权限”“警情简报”等可理解标签。对应代码在 `basic.vue` 第 105–107 行。

影响：视觉上方是中文业务名称，实时摘要却突然改成实现标识；屏幕阅读器用户尤其难以将值映射回选项，第一次阅读 API 的开发者也容易把传输值和展示文案混淆。

建议：用选项值到中文标签的映射构造摘要，并保留“无”空态。若摘要只用于调试，明确标注“选中值”并与面向用户的状态分开。

### [P2] HUD 主题预览使用小型原生 checkbox

复现：在任一 Demo 查看“HUD 深色主题”控件。`basic.vue` 中它是未指定样式的原生 `<input type="checkbox">`；外围 label 仅设 `min-height: 32px`，而业务选项本身为触屏设置 44px 高度。

影响：预览入口和 Lx 业务控件的外观、触控面积不一致，手机或触控设备上的目标明显更小；它是用户开始预览深色主题的唯一入口。

建议：复用库内开关控件或提供明确的开关外观，并把整条 label 的触控高度提升到至少 44px，同时保留键盘可见焦点。两页采用同一实现。

## Persona 走查

**Jordan，第一次使用组件文档的前端开发者**：先看示例，再确认 v-model 和可复制代码。中文选项和 Props 表能快速定位用法；底部摘要中的 `video`、`briefing` 不像业务标签，Radio 的跨组联动也会让他误判组组件行为。修复建议是用中文标签播报值并隔离每个 Demo 的模型状态。

**Sam，键盘与屏幕阅读器用户**：沿标题进入组后依靠原生 checkbox/radio 语义选择。源码和现有测试覆盖组名称、半选混合态、方向键跳过禁用项、可见焦点及 44px 业务选项高度，这是明确优势；主题预览 checkbox 仅 32px 高且未设置组件样式，触控体验和视觉焦点仍需统一。当前子任务无法创建可截图的浏览器标签，因此没有验证实际辅助技术朗读或焦点外观。

- 实现源码已有 `LxCheckbox`、`LxCheckboxGroup`、`LxRadio`、`LxRadioGroup` 四个组件；组支持水平/垂直排布、`name` 传导、禁用继承和显式覆盖，复选组将组选项约束为字符串或数字。

- 中文 API 文档已有 Props/Events/Slots、全选/半选代码、设计稿对齐说明、无障碍和宿主适配内容。
- `other-admin/admin-vue3/tests/unit/lx-checkbox.test.ts` 与 `lx-radio.test.ts` 源码覆盖值变化、组选中、垂直布局、禁用、`ElForm` 禁用继承、半选与旧 `label` 契约。
- `other-admin/admin-vue3/tests/e2e/lx-checkbox-radio-docs.spec.ts` 源码覆盖文档 Demo 的状态、hover、HUD 深色、Radio 方向键与减少动效，以及 375px 视口下触控高度和横向溢出。

## 次要观察

- Checkbox 文档已提供从子项计算全选/半选的完整代码示例，能解释静态半选行的实现方式；建议 Demo 中的静态行继续保持明确的“状态示例”定位。
- Radio `lastAction` 会说明最近一次变更的字段和值，但它只反映最近操作；将两个示例状态拆开后，最好同步显示各组选中值，避免一个摘要看起来代表整页状态。
