## Findings

### P2：缩窄视口时可能隐藏当前焦点所在的面板

位置：`linkx-fe/src/components/LxTransferPanel/index.vue:60`、`:331`、`:336`、`:654`、`:856`、`:1646`。

`mobilePanel` 初始固定为 `source`，只由移动端两个切换按钮更新。桌面布局下切换按钮隐藏，但左右面板都可聚焦；如果焦点在右侧已选列表或删除按钮上时视口缩到 767px 以下，右侧面板会因 `mobilePanel !== 'selected'` 获得 `display: none`。窗口 resize 处理只更新行高和滚动提示，没有在隐藏面板前保留可见面板或迁移焦点，键盘焦点会落入隐藏区域或退回文档。现有 E2E 跨断点用例聚焦的是左侧树，没有覆盖右侧焦点跨入窄屏的路径。

建议在响应式切换时保留当前活动面板，或在隐藏含焦点的面板前将焦点移至对应的移动端切换按钮，并增加“桌面聚焦右侧控件后缩窄视口”的浏览器用例。

### P3：`itemSize` 未约束正有限值，零值会使虚拟窗口变空

位置：`linkx-fe/src/components/LxVirtualTree/index.vue:204`、`:207`、`:209`、`:432`；类型位置：`linkx-fe/src/components/LxVirtualTree/types.ts:15`。

窗口起点和渲染数量直接用 `props.itemSize` 做除法，节点行 CSS 高度也直接使用该值。传入 `0` 时窗口起止计算变成 `NaN`，`visibleRows` 切片为空；此时 `flatNodes` 仍非空，空态也不会显示，用户看到的是空白树。负数或非有限值同样会产生错误的窗口范围或无效 CSS。公开类型和文档目前只声明 `number`，没有正值约束。

建议在窗口计算与行样式使用前统一校验有限且大于零的行高，并用边界用例覆盖零、负数和非有限输入；或者明确文档前置条件并在开发期给出可见诊断。
