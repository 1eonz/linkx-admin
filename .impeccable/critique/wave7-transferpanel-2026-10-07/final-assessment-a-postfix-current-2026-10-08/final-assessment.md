## 整体印象

桌面上可快速判断“谁在候选范围、谁已获选、哪些批量动作可用”；危险清空有合理确认，HUD 下视觉语义完整。当前 320px 修复让长名称正常换行且列表项自身没有横向溢出，这是一个可观察的改善。窄屏下仍是两栏纵向展开，完成选择后回看结果需要更多页面滚动；文档多列表格也没有手机阅读所需的行宽。

## 优势

- **全量和筛选操作可区分。** “全部加入 / 全部移除”文字始终可见；只有输入筛选后才出现“全选筛选结果 / 反选筛选结果”。限制状态也保留短提示，并将完整说明关联给按钮。
- **继承语义落在控件旁。** 浏览器读取到“仅向所选机构的直属下级继承；关闭后停止下级继承。”且复选框的 `aria-describedby` 指向该说明。宿主负责提供真实规则的边界与文档一致。
- **HUD 主题和危险反馈保持一致。** 实测 HUD 确认框背景为 `rgb(11, 18, 32)`、标题为 `rgb(247, 137, 137)`、危险按钮为 `rgb(245, 108, 108)`；取消后已选数量仍为 5 项。
- **主题恢复修复通过两种生命周期场景。** Demo 自己开启 HUD 后卸载会清理 Demo 写入的类；若根元素在 Demo 挂载前已有 `dark` 与 `lx-theme-hud`，关闭 Demo 开关并卸载后，两类仍保留。

## 优先问题

1. **[P2] 窄屏上候选树和结果清单纵向相接，选后核对要长距离滚动。** 在 375×812 下组件从页面 y=611 开始，高 842px；320×760 下从 y=651 开始，高度相同。用户完成候选选择后，需要向下浏览结果，再回到上方继续操作。建议在窄屏提供“待选 / 已选”分段切换，并让已选数保持可见；如果保留纵向布局，至少提供跳至已选清单的短路径。建议 `/impeccable adapt`。

2. **[P2] 手机视口内的 Props / Events 多列表格阅读宽度不足。** 320px 全页截图显示文档内容虽无整页横向溢出，但类型和说明列被挤窄，中文说明换行密集，难以横向比较各属性。建议小屏仅让表格容器滚动并固定名称列，或改为单项纵向属性条目。建议 `/impeccable adapt`。

3. **[P3] 移动文档首屏仍需滚动到核心演示。** 在 320px 和 375px 下，面板分别从 y=651 和 y=611 开始；打开页面后首屏主要是标题、简介和折叠的示例设置。对来文档页确认组件行为的开发者，核心交互要滚动后才出现。建议标题后先放一个紧凑示例摘要，再将操作参数与长说明置于后续区域。建议 `/impeccable layout`。

## 认知负荷

按 Critique 认知负荷的八项检查，失败 1 项，为低负荷：

- [x] 单一焦点：主任务集中在选择与确认已选项。
- [x] 信息分组：左右面板及中央穿梭操作有清楚边界。
- [x] 相关信息就近：编码、状态、未加载原因和继承范围与对象并列。
- [x] 视觉层级：候选与结果标题、计数和主操作易定位。
- [x] 一次一个主要决定：当前选择、筛选和高风险清空有分别明确的交互。
- [x] 最少选项：每个批量动作组不超过四个主要选项；状态选择在折叠区里另成一组。
- [x] 工作记忆：已选数量、编码和状态不要求跨页记忆。
- [ ] 渐进披露：同页完整 Props / Events 表与持久化代码示例默认铺开；在手机阅读时，次级细节占用较长滚动路径。建议保留内容但让窄屏读者更易跳转或折叠。

低负荷的结论针对一个选择动作；手机上比较两组清单的额外滚动成本已单独列为优先问题。

## 情绪路径

从选择到确认，计数和批量反馈提供即时把握感；旧授权被移除前先说明无法核验名称并允许取消，降低误清空焦虑。错误态保留选择并提供重试，结束点是可恢复状态。示例明确是本地数据，没有把 Mock 行为暗示成后端联调结果。

## Persona 红旗

- **Alex（熟练用户）**：可筛选并对匹配节点批量全选或反选；上限状态可见且阻止无效写入。缺少专用键盘快捷键，极高频全键盘操作者会多按几次 Tab，但列表焦点路径有效。
- **Jordan（首次使用者）**：继承复选框的本地说明讲明了直属下级和关闭效果；若实际宿主未传 `inheritChildDescription`，用户将只看到“保留下级继承授权”，不一定知道授权对象。接入方必须按真实业务传说明。
- **Mina（手机用户）**：320px 下长机构名称可以换行，页面和列表项均无横向溢出；候选与结果面板仍纵向占据较长页面，手机上连续选择与复核需要更多滚动。

## 细节观察

- 1440px 桌面组件为 865px 宽，布局内滚动而没有页面横向溢出；375px 和 320px 页面 `scrollWidth` 与 `clientWidth` 相等。全量按钮在三种宽度均能看到完整文案。
- 320px 下长名称“历史授权单位（记录中）：跨区域应急联动研判与协同处置权限”自然换行，已选行内容宽度 `252px`，其 `scrollWidth` 仍为 `252px`，没有文本横向裁切。
- 空树返回“暂无数据”，右侧五项选择保留并单独显示；这是已选键可先于树数据加载的预期语义。
- 加载态 DOM 实测 `aria-busy=true`、组件根 `inert=true`、透明度 `0.62`；错误态有 `role=alert`、保留选择文案和“重试”。重试后回到正常数据，选择数仍为 5。
- 上限为 5 项且已选 5 项时，“全部加入”和筛选全选均禁用；短提示是“已达上限 5 项”，完整说明分别指出无法再加节点及筛选有 1 项未选、还可选 0 项。
- Tab 能从已选筛选框到达已选列表。列表有可访问名称、`tabindex=0`、内部滚动和 2px 蓝色焦点环。
- 模拟 `prefers-reduced-motion: reduce` 后，面板及已选列表 transition / animation 为 `0.00001s`，动画名称为 `none`。

## 设计问题

- 对手机用户而言，是否可以让待选与已选清单通过短切换进行比较，同时让已选数量常驻？
- Props 与 Events 表格在窄屏上的目标是保留横向对照，还是把可读行宽放在首位？
- 继承范围是权限正确性的一部分；是否要在接入示例与文档中把 `inheritChildDescription` 列为必填业务说明？
