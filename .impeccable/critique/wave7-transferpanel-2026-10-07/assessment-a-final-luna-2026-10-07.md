## Design Specificity Verdict

这是围绕 LinkX 权限分配工作的专用控件，不是通用穿梭框换皮。组织树、节点编码与状态、保留未加载的既有键、下级继承开关，以及深色 HUD 共同建立了明确的警务权限场景；虚拟树、双侧清单和批量穿梭也符合管理者的任务模型。

实现保留了设计标本的 `5:2:5` 轨道、`380px` 面板、32px 树行、编码/状态展示和暗色值守主题。差距主要在样例覆盖：标本以 `1,420` 节点、12 行可视区和五条已选项展示密集层级；当前 Demo 只有 53 个节点、两个已选项，额外归档节点为扁平禁用项。实际虚拟渲染已成立，但长层级、千级节点性能和大列表扫描仍未由文档示例证明。设计 HTML 中的旧 API 标本也与现行文档契约不一致。

## What's Working

1. **权限语境保留完整。** 两侧标题、未加载键、编码/状态和继承开关都在同一工作区里，列表与待选池各自滚动。
2. **响应式和可访问性基础可靠。** 375px 无横向溢出，主要移动操作为 44px；面板有标题关联，键盘过滤清除焦点实测可见。
3. **状态反馈可以复核。** Demo 保留当前值处理加载和错误，错误提供重试；清空有撤销，空树和未加载选中键也能正确区分。

## Priority Issues

### P0 / P1：无

本次没有观察到阻断任务完成的问题，也没有需要据此判为发布阻断的发现。

### [P2] 688px 桌面内容列让“全选/反选”拆成竖排文字

`index.vue:262` 的两项头部动作在桌面 CSS 下没有最小宽度或不换行约束；`index.vue:522` 仅设置行内 flex、间距和 padding。独立浏览器中根宽 688px、每个按钮宽 `30.41px`，截图可见“全选”和“反选”按单字换行，点击目标也窄。文档页的侧栏和页内导航使 1440px viewport 仍只有 688px 内容列，因此桌面 viewport media query 无法识别容器过窄。

建议为动作保留足够的最小宽度并禁止文字折行，或用容器宽度触发布局压缩策略，同时确保标题不会与动作争抢空间。

### [P2] Demo 能证明虚拟滚动，不能证明标本承诺的千级规模

`demo/basic.vue:55` 在现有示例树上再生成 48 个扁平归档节点；运行中确有 `1696/263px` 的滚动内容比，DOM 保留 21 行，虚拟化本身可见。但与 `code.html:195,245,497` 的 1,420 节点、12 行标称相比，样例量相差约 27 倍，且归档节点均禁用、树层级单一。文档读者无法从默认 Demo 验证长层级、活跃/禁用混合和千级列表滚动性能。

建议在本地生成稳定的 1,420 节点层级样例，保留少量默认展开，并让长列表滚动与状态分布进入初始演示；这是演示数据，不应表述成真实后端联调。

### [P2] 权限“清空”是否可恢复取决于每个宿主

`index.vue:197-200` 的 `clearAll()` 先发出空数组，再发 `clear-all`；`lxtransferpanel.md:58` 明确把确认/撤销留给宿主。Demo 用 `basic.vue` 的撤销状态证明了可恢复路径，但生产宿主若把 `v-model` 直接持久化，可能在确认策略介入前就写入空权限。此处是高风险集成契约，不是要求通用展示组件引入业务确认框。

建议把宿主确认或撤销要求紧邻 `clear-all` 使用说明，并给生产接入示例展示“确认通过后再提交空值”的时序。

### [P3] 设计 HTML 中的接口代码仍是旧契约

`design/虚拟滚动树 + 双栏穿梭/code.html:712-716` 仍写“最大 400px”、`onNodeChange`、`onClearAll` 与 `any[]`；现行文档使用 `update:modelValue`、`change`、`clear-all`，且 `panelHeight` 只声明默认 380，不承诺 400px 上限。它不会破坏当前运行页面，但作为组件标本容易让维护者误把静态稿当作 API 来源。

建议同步更新该静态契约代码或显著标记为历史构想，确保文档 Props/Events 是唯一可执行契约。

## Cognitive Load Assessment

结论：**中等负荷，2 项失败**。

- **分组、主线与工作记忆：通过。** 待选树、中心移动和已选清单边界清楚；计数、节点状态和未加载键都留在当前视图；主要任务无需跨页。
- **渐进披露：通过。** 六个 Demo 场景/开关默认收在“示例状态与主题”折叠区，生产主任务不会一进入就被测试工具栏打断。
- **视觉层级：失败。** 在 688px 内容列，“全选/反选”逐字换行，原本的次级操作变成突兀的竖排块；11px 编码/状态在窄树行中也容易与名称争宽度。
- **最少选项：失败（展开 Demo 时）。** 同一状态组会显示四个互斥场景和两个独立设置，共六个控件；可保留调试能力，但可进一步把互斥场景合并为一个选择器。
- **一次一事与上下文：通过。** 搜索、勾选、批量加入和右侧核对都在同一个区域内，状态变化也有文案确认。

## Emotional Journey

- **进入：** 双栏和面板标题很快建立“从组织树授权到结果清单”的方向；默认已选数和状态标签提供上下文。
- **操作：** 选中数量立即更新，状态消息说明新增结果；在 375px 上两栏自然堆叠，无横向拖动。
- **高点：** 清空后的“撤销清空”让误操作有明显回路，重试也能恢复正常态。
- **低谷：** 688px 内容宽度下动作文字换行使第一个印象偏拥挤；错误时全组件变暗并禁用，虽然数据仍在，用户只能查看而不能继续核对操作。
- **结束：** 真正空选时右栏提示“暂无分配权限，请在左侧勾选”，给出明确下一步；错误也提供重试。
