# LinkX 组件文档设计评审

**评估日期：** 2026-10-07  
**目标：** `linkx-fe` VitePress 文档的 LxDynamicForm、LxUpload、LxDatePicker 页面  
**设计模式：** Read（组件库文档；含可操作示例）  
**结论：** 31/40，Good；发现 2 项 P2 和 1 项 P3。没有 P0/P1。

## 设计特异性

交互示例明显取材于 LinkX 的勤务、布控和告警场景：“排班数据导入”“任务封面”“专项布控日期区间”“告警汇聚窗口”等字段使示例不易与通用商业表单混淆。浅色文档外壳与低饱和控件、HUD 深色预览形成清楚的层级，图标、标签和状态沿用一致的组件语言。

外层阅读框架仍是常见的文档站布局；产品气质主要来自示例数据和交互，不来自导航或版式本身。整体属于“示例内容有领域特征、文档容器可互换”，不是完全定制化的阅读体验。

## 整体印象

文档以可运行的示例承接 API 说明，成功、失败和恢复状态都能直接验证，阅读者不必只凭 Props 表推断行为。主要机会是让使用者更早进入示例，并让窄屏下连续出现的必填错误更容易逐条扫描。

## 做得好的地方

- 动态表单将主表单、演示设置和字段类型预览分层；折叠设置后可直接输入，另有链接打开 14 种字段类型的搜索预览。
- 上传失败行同时显示失败徽章、文件名、原因和重试动作；触屏宽度下仍可辨认并操作，失败后确实能重试成功。
- 日期选择器在移动宽度切换为单面板，快捷范围按钮在日历上方横排；ArrowDown、ArrowRight、Enter 和 Escape 均能完成预期操作。

## 优先问题

### [P2] 上传页移动首屏被状态说明占满

**证据：** 375×812 的 `lxupload-touch-00-top.png` 显示标题后连续四段说明；首屏没有可操作上传区，主要在解释三态、进度实现、状态徽章和减少动效。用户需要滚动读完这段说明才能到“排班数据导入”示例。桌面 1365×900 的 `lxupload-desktop-00-top.png` 也只露出示例上半部。

**影响：** 组件库使用者打开示例页后，先遇到实现细节而非上传控件，延迟了验证最常见任务的时间。

**建议：** 把首段压缩为用途、格式限制和 Mock 说明；将状态规范整理为示例后的分组说明或折叠内容，让上传示例在移动首屏更早出现。

**建议命令：** `/impeccable distill`

### [P2] 动态表单窄屏校验提示过于紧凑

**复现：** 在 LxDynamicForm 页面点击“提交校验”而不填写必填项。浏览器将焦点移到“任务名称”并关联其错误说明，另外“访问密码”和“任务类型”也显示错误。375×812 截图 `lxdynamicform-touch-03-validation.png` 可见每条错误都紧贴下一字段标签；错误出现后这一列的红色文字连续堆叠。文档底部还用“请填写标红的必填字段”再次概括错误。

**影响：** 用户能找出问题，但快速扫视时字段标签与前一项错误的边界不够松，多个必填项同时失败时增加误读机会。焦点定位及错误关联本身正常，所以是 P2 而非阻断问题。

**建议：** 窄屏增加表单项错误文案与后续标签间距；保留逐字段错误，将底部通用提示弱化为一次性摘要或可跳转摘要，避免重复占用注意力。

**建议命令：** `/impeccable layout`

### [P3] 日期选择器移动示例需要多次纵向滚动

**证据：** 375×812 的 `lxdatepicker-touch-00-top.png` 在首屏只显示区间示例和“单日和月份”开头；浏览器记录的 Demo 高度为 1526 CSS px，之后还包括常用范围、日期标记、日期时间、校验及禁用/只读示例。顶部的“本页导航”可以跳到文档标题，但示例内部没有对应的快捷定位组。

**影响：** 需要比较特定状态（例如校验或只读）的读者要滚动较长距离。API 项目完整且页面导航存在，影响可绕过，列为 P3。

**建议：** 为 Demo 增加贴近顶部的示例目录，或将日期标记、日期时间、禁用/只读等低频示例折叠；保持 Props 和完整示例仍可查阅。

**建议命令：** `/impeccable adapt`

## 认知负荷

总体为**中等**。主要表单按“任务信息 / 任务状态 / 附件”分组；动态表单的列布局、禁用和主题选项折入“演示设置”，字段预览另行折叠，降低初始干扰。上传和日期页面也按控件区域分组。

Checklist 失败 2/8：

- **单一焦点：** LxUpload 移动首屏有多段状态机制说明，实际上传任务未露出。
- **信息分块：** 上传三态、文件列表、进度和动效细节以长段落承载；动态表单 Demo 后的行为说明也较长，适合改为短分组或表格。

其余六项总体通过。动态字段类型预览可搜索并按五组浏览；快捷日期控件的日期网格自然提供超过四个候选值，按星期和月份分组，属于日期选择任务本身的复杂度。实测到的主要操作组不超过四个选项。没有观察到需要跨页面记忆才能继续操作的步骤。

## 情绪路径

标题和具体示例给出明确预期，展开控件后能立即试用；表单错误和上传失败带来短暂低谷，但都显示在出错项目旁，上传恢复动作也直接可见。成功提交后有“表单已校验：夜间巡防任务”确认。整体结束状态清楚。移动端上传页在读者到达示例前的长说明，是最明显的早期摩擦。

## Persona 风险

- **Jordan（首次使用者）：** “排班数据导入”标题明确，但上传页首屏先出现“聚合进度面板”“Mock”“`transform`”等开发术语，交互区又在首屏以下。快速浏览者可能误以为这页主要是实现规范。表单、上传和日期本身的中文动作文案清楚。
- **Sam（依赖键盘/辅助技术）：** 键盘 Enter 能启动文件选择；单日日期字段的 ArrowDown 打开面板，ArrowRight + Enter 将 `2026-09-15` 改为 `2026-09-16`，并关闭弹层；Escape 关闭区间日历。空表单提交会把焦点放到首个错误字段。未做真实 NVDA/VoiceOver 或 200% 缩放，不能据此确认完整读屏/放大体验。
- **Casey（移动、容易被打断）：** 375px 下各 Demo 无页面横向溢出，主要按钮可见且布局会换行；上传页需要先滚动越过说明才能开始试用。示例状态明确只存于当前页面，刷新/离开后的状态保存不属于该 Demo 的能力。

## 次要观察

- 所有六个浏览器页面响应均为 HTTP 200；桌面和触屏视口均未发现页面级横向溢出。
- HUD 深色示例切换成功。日期 HUD 弹层保留 `lx-theme-hud` 类，日期范围快捷项在两种视口都填入 `2026-10-05` 至 `2026-10-11`。
- 六个上下文都设置 `prefers-reduced-motion: reduce`；页面均报告媒体查询匹配，观察到的 CSS 动画/过渡时长为 `0.00001s`。本轮未在正常动效偏好下比较两套视觉。
- 上传 Mock 的预期失败触发一次 `UploadAjaxError` 控制台错误；UI 显示“上传服务暂不可用，请重试”，重试后状态变为“上传成功”。这不是后端请求失败。动态表单桌面另记录到一条无 URL 的 404 console 文案，未发现 page error 或可归因的失败请求；未将其算作已确认用户问题。
- 截图使用 Microsoft Edge 154.0.4258.53（Chromium），每个页面/视口都新建 context 和 page；手机视口用触屏模拟，未使用真实手机。读屏器、200% 缩放、实际拖拽文件和真实后端上传未验收；上传通过浏览器文件选择器加入本地 CSV，由 Demo 内存 Mock 传输。
- 本轮没有运行 detector，没有查看 overlay，也没有读取或合并其他评估产物；没有修改产品源码。
