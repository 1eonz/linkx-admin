## 设计特异性

该页面整体符合 LinkX 后台组件库：蓝色主色、HUD 深色主题、业务字段和 Element Plus 交互约定使它不完全像通用表单 Demo。左侧组件导航和右侧目录仍是标准文档框架，但不妨碍主体验收。

**单边线判断**：本轮独立浏览器检查中，原先“控件外圈与组件边界错位/出现双圈”的现象没有复现。多选获得焦点时，只有组件自身 1px 边线变为主题色；`box-shadow: none`，`outline-style: none`，焦点态与普通态的边界盒尺寸一致。浅色为 `rgb(0, 96, 169)`，HUD 深色为 `rgb(56, 189, 248)`。桌面 1280×720 下控件为 279.5×32px；390×844 移动视口下为 301×32px，未见横向溢出。就“外圈未对齐/双圈”这个具体问题，单边线修复有效。

焦点状态在视觉上仍比输入框、日期框轻，因为后两者另有外侧光晕。多选自身的蓝色线清晰且贴边；若用户所说的“还有问题”指线条显得过细或缺少焦点重量，这部分仍未解决。增加强调时，优先评估不改变外边界的 2px 内侧焦点描边，避免恢复错位的外圈。

## 认知负担与情绪

Demo 中主要字段有标签，选择操作直接可见；折叠标签将第二项收进“+1”，能省空间，但完整值需要展开或查看提示。没有单一决策点超过 4 个可选项：部门下拉只有 3 项；顶部按钮展示多种尺寸和语义色，属于组件对照样例而非用户任务。

从看到字段到选中部门的情绪路径平稳：焦点色、已选项和下拉勾选提供确认；触发表单校验后，错误文字保留并指向责任部门，能支持恢复。移动视口切为单列，当前没有挤压多选标签。未测试读屏朗读、完整键盘顺序或真实后端流程。

## 优点

- 浅色和 HUD 深色下，多选外边线都落在自身控件边缘，没有第二圈或焦点态尺寸跳动。
- “指挥中心 +1”、清除按钮和展开列表中的已选勾选状态让折叠多选仍可辨认和恢复。
- 移动视口下表单切为单列，多选控件维持完整宽度，未产生页面横向溢出。

## 优先问题

1. **[P2] 同一表单的焦点强调不一致**：下拉使用单条 1px 主题边线，而文本输入/日期控件在边线外还有 2px、15% 主色光晕。外边界现在对齐，但用户会感到焦点重量不同。建议将下拉与其他表单控件统一为同一焦点策略；若不使用外圈，则把其他控件也评估为边界内的强调样式。
2. **[P2] 1px 单边线可能仍显得偏细**：这不是错位缺陷，且颜色对比明显；但截图缩放或低清屏上视觉重量比相邻控件轻。若实际反馈针对“看起来弱”，可评估 2px 内描边，并再次确认边界盒和标签没有位移。
3. **[P2] 多选焦点错误态无法从当前 Demo 验收**：点击“校验表单”只给必填的“任务名称”和单选“责任部门”报错；“协同部门”没有必填规则，真实错误态不存在。不能把单选红边当作多选错误态证据。若需要展示该视觉状态，应增加独立的纯展示状态或在 Demo 说明其不适用，不要仅为展示而改变业务必填语义。
4. **[P3] 焦点用途提示不在字段旁**：说明段写明协同部门用于检查键盘焦点，但位于 Demo 之后。初次访问者不一定发现焦点状态需要点击/Tab 才出现；可将简短状态说明放在 Demo 控件组附近。

## 相关用户视角

- **Sam（键盘/辅助技术用户）**：焦点边线在浅色和深色都可见；本次通过鼠标建立焦点，完整 Tab 流程和读屏对“+1”及错误消息的关联尚未验证。重点风险是同一表单不同控件的焦点强调不一致。
- **Alex（熟练后台用户）**：多选当前两个已选项，折叠后显示一项加“+1”；可展开查看完整列表，当前选项的勾选状态清楚。未发现阻断操作的问题；键盘批量选择效率未测试。
- **Jordan（初次使用者）**：字段名与部门选项足够直观；“+1”能说明还有值，但不直接列出第二个部门。若对值有确认要求，需要展开列表或使用标签提示。

## 次要观察

- 当前 Demo 的真实校验错误是必填字段校验；多选字段没有错误信息，报告或截图应准确标注为单选责任部门错误态。
- 当前评估覆盖桌面 1280×720、移动 390×844 和两种主题；没有检查更低高度设备、200% 浏览器缩放、读屏或真实后端。

## 证据记录

- 独立 CUA 标签访问目标页面并直接观察浅色桌面、HUD 深色桌面、浅色移动与 HUD 深色移动的多选焦点态。
- CUA 页面计算样式：桌面浅色多选 `border: 1px solid rgb(0, 96, 169)`、`box-shadow: none`、`outline-style: none`、`279.5×32px`；桌面 HUD 深色边线 `rgb(56, 189, 248)`，同为 `279.5×32px`。移动 HUD/浅色下均为 `301×32px`，焦点边线分别为主题色，`box-shadow: none`，`outline-style: none`。
- 点击“校验表单”实际触发 Element Plus 校验，返回“请输入任务名称”和“请选择责任部门”；多选没有错误类或错误文案。单选责任部门聚焦错误态为 `1px solid rgb(247, 137, 137)`，无外部阴影。
- `.impeccable/critique/evidence-2026-09-28-assessment-a-user-feedback-final/` 下存在 5 张 Playwright PNG。它们的自动截图在焦点颜色过渡开始时取样，颜色没有可靠呈现最终状态；不把这些 PNG 当作单边线视觉结论的依据。上述结论依据独立 CUA 标签中等待状态稳定后的页面截图与计算样式。
