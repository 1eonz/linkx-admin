# LxDynamicForm 独立设计评审 A

## 范围与方法

独立检查 `LxDynamicForm` 源码、字段子组件、Demo、中文 API 文档和设计说明，并在新浏览器标签打开 `http://127.0.0.1:4174/components/lxdynamicform.html`。实际检查桌面默认表单、展开的演示设置、远程候选失败、必填校验和 HUD 深色主题。评审未读取 Assessment B 结论，也未修改仓库文件或运行 detector。

评审时页面视口约为 1264×713。未验证窄屏、200% 缩放、完整键盘流程或 NVDA/VoiceOver 实际朗读；对比度未量化，不能据截图认定违反 WCAG。

## 设计判断

页面通过任务名称、巡防、负责人和现场图片建立业务语境，整体沿用克制的管理后台表单设计。视觉层级和字段交互符合组件库用途，但布局仍较通用，替换成其他管理后台品牌也基本可以复用。

## 认知负荷

结果为中等，检查项有 2 项未通过：

- **分块**：文档侧栏“数据录入”分组展开后同级组件链接超过 4 个，初次访问者需要逐项扫描。
- **最少选择**：同一组可见多个同级页面链接，增加组件定位时的选择量。
- 通过项：Demo 默认先显示主要表单，低频选项收在“演示设置”；字段按网格组织；条件字段仅在相关模式出现；主要动作集中在表单底部。

## 优点

- 默认页面先给出可填写表单，低频 Mock 与布局设置收在折叠区。
- 远程失败和校验错误靠近问题字段，恢复动作清楚。
- Demo 覆盖联动、禁用、上传列表、失败和 HUD 主题，并说明内存 Mock 与真实后端的边界。

## 优先问题与处理

- **P2，长表单缺少语义分组示例**：字段增加后可能成为连续长表单。已在中文文档明确由宿主按业务语义添加分区标题或拆成步骤；DynamicForm 本身不提供分步状态。
- **P2，初次接入缺少最小示例**：完整参考表前不容易确认最小配置。已在中文 API 文档新增最小 schema 示例。
- **P2，文档侧栏同级链接过多**：已确认“数据录入”分组超过 4 项；属于跨组件文档信息架构问题，本波登记为后续事项，未改动全站侧栏。
- **P3，加载状态不易稳定检查**：原候选请求只有短暂 loading 窗口。已在 Demo 增加独立“加载中”操作，可固定显示状态，并由成功、空结果或失败操作恢复。

## 用户画像风险

- **初次接入者**：最小示例已补；仍需理解 schema 与受控值契约。
- **熟练开发者**：受控值、自适应布局和多图上传有帮助；复杂长表单需宿主设计分区。
- **键盘/读屏用户**：源码和 AX 树可见字段名称、错误反馈和操作名称；自定义插槽仍要求宿主传递描述 ID 并落实禁用语义。本轮未执行真实读屏器验收。

## 情绪路径与问题

默认界面直接给出主要任务；错误时字段提示、焦点和重试降低恢复成本。示例是内存 Mock，不能推断真实提交确认或数据持久化体验。

留待后续评估的问题：schema 增长时何时切换到分区或步骤；全站组件侧栏如何减少同级导航负担；是否需要更多固定异步状态的 Demo 控件。

问题已并入计划并继续推进，因此本轮不暂停等待用户回答。
