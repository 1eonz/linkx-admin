# 直播间价格趋势与购买决策后台 PRD

- 版本：v1.0
- 日期：2026-10-10
- 产品形态：个人使用的 Web Admin 后台
- 核心目标：记录直播间公开报价，比较历年变化，辅助个人购买决策
- 主价格口径：直播间公开展示的整套商品报价
- 辅助信息：赠品、满减、报价条件、来源凭证

## 1. 产品定位

本产品用于记录 618、双十一及日常直播中同一商品的历史直播间报价，回答：

1. 当前直播间报价是多少？
2. 相比过去同规格、同活动的报价是上涨还是下降？
3. 这个价格是否值得我关注或购买？

第一版不把个人最终到手价作为主指标。红包、会员、平台满减和凑单条件因人而异，直播间公开报价才适合作为历年趋势的统一口径。满减和个人实际支付金额保留为辅助信息。

## 2. 产品目标与范围

### 2.1 第一版目标

- 建立商品、品牌、品类、规格、直播间和活动基础数据。
- 录入、校验、查询直播间报价，并保留来源凭证。
- 查看同一规格的历年趋势、去年同期比较和直播间比较。
- 独立记录用户兴趣、购买意愿、目标价和购买结果。
- 支持 CSV 导入、导出和站内目标价提示。

### 2.2 第一版暂不做

- 自动抓取直播、直播视频识别和全平台实时监控。
- 自动计算每个人的满减、红包、会员权益后到手价。
- 赠品现金估值、价格预测、综合性价比评分。
- 公共社区、商业导购、多用户权限体系。

建议先覆盖两个品类、两到三个直播间和三十到五十个常看商品，优先整理有来源的 618、双十一记录。

## 3. 核心产品原则

1. 直播间公开报价是主价格。所有默认曲线、历史最低价和活动比较都使用该字段。
2. 满减是辅助字段。记录金额或规则，但不自动从主价格扣除。
3. 同规格才能直接比较。容量、数量、组合、版本不同，必须拆成不同规格。
4. 赠品单独展示。不把赠品折算为现金，也不因此改变主价格。
5. 价格判断与购买意愿分开。系统描述价格历史，用户记录自己是否想买。
6. 所有历史结论注明范围。“历史最低”只表示当前已收录、已筛选范围内的最低报价。

## 4. 用户与核心场景

第一版以个人管理员为主要用户，管理员同时负责录入和查看数据。

| 场景 | 用户动作 | 结果 |
| --- | --- | --- |
| 直播前 | 查看关注商品、目标价和去年报价 | 明确可接受价格 |
| 直播中 | 录入报价、赠品、满减和来源 | 快速得到历史位置 |
| 大促比较 | 选择 618 或双十一年份 | 查看同规格历年变化 |
| 跨直播间 | 选择同一规格 | 比较各直播间报价 |
| 个人决策 | 标记想买、等降价或暂不考虑 | 形成购买清单 |
| 购买后 | 记录实际购买和感受 | 保留决策复盘依据 |

## 5. 价格口径与比较规则

### 5.1 直播间报价定义

“直播间报价”是直播间对指定销售组合公开展示的整套售价，单位为人民币元。

- 50ml 单瓶 399 元，主价格为 399 元。
- 50ml 两瓶装 699 元，主价格为 699 元，规格记录为数量 2。
- 定金 40 元、尾款 359 元，主价格为 399 元；定金和尾款辅助记录。
- 只看到定金或“低至”金额、无法确认整套价格时，只保存为草稿。
- 直播间明确展示“领直播券后 399 元”，记录 399 元，并标记已含直播券，避免重复扣减。
- 平台满减、个人红包、会员优惠不自动扣除。
- 仅限会员或特定用户的报价标记为条件报价，默认不进入通用趋势。

### 5.2 赠品与满减

赠品记录名称、规格、数量和描述，不折算现金价值。满减可记录金额和规则，例如“满300减50”，但不推算该商品一定减免50元。

页面顺序为：直播间报价 → 历史比较 → 赠品与满减 → 来源和条件。

### 5.3 可比规格

默认直接比较必须满足：同一商品、同一版本、同一容量/重量、同一数量、同一销售组合和相同报价适用人群口径。

- 50ml 与 100ml 分开建规格。
- 单瓶与两瓶装分开建规格。
- 单品与含多个正装的套装分开建规格。
- 配方或型号变化时新建版本。
- 仅外包装变化且确认内容一致，可人工建立关联并留下说明。

可以显示元/100ml、元/kg等单位价，但不能据此把不同规格标记为同款历史最低，也不计算赠品单位价。

### 5.4 历史记录解释

“历史最低”展示为“已收录最低报价”，同时显示筛选范围、时间范围和样本数量。没有记录表示暂无数据，不代表价格为零或没有销售。历史曲线只连接真实报价点，不填充中间日期。

## 6. 信息架构

| 模块 | 主要内容 |
| --- | --- |
| 总览 | 关注商品最新报价、目标价命中、待核实记录 |
| 商品库 | 商品、品牌、品类、规格 |
| 报价管理 | 报价列表、录入、编辑、校验、导入 |
| 活动对比 | 历年 618、双十一等活动比较 |

## 7. 功能需求

### 7.1 总览

- 展示关注商品最近新增的有效报价、目标价命中和待核实报价。
- 区分报价发生时间与录入时间。
- 支持按活动、直播间、品类筛选。
- 提供新增报价和进入商品详情入口。

### 7.2 商品与规格管理

商品字段：品牌、品类、名称、别名、状态。  
规格字段：版本、容量/重量、单位、数量、组合说明、状态。

商品可归档，归档后保留历史报价。已参与报价比较的规格不能直接改写影响比较的字段；改版应新建规格。第一版不自动合并相似商品，只做人工检查提示。

### 7.3 报价管理

新增流程：选择商品规格 → 选择直播间和活动 → 填写发生时间与直播间报价 → 补充来源、赠品、满减 → 保存。

必填：商品规格、直播间、报价发生时间、直播间报价、报价条件类型、来源类型和来源说明或凭证。

可选：活动、直播场次、赠品、辅助优惠、定金、尾款、运费、有效截止时间、备注和截图。

- 新增默认状态为“待核实”；确认规格、价格、来源后变为“有效”。
- 草稿、待核实、无效、归档不参加默认统计。
- 修改有效报价需填写原因并保留修改前后日志。
- 同规格、同直播间、同场次、同报价和条件重复时提示。
- 同日不同场次或不同赠品可以分别保留。
- 价格异常只提示人工核对，不自动删除。

### 7.4 商品详情与趋势

展示顺序：

1. 商品名称、规格、最近报价、直播间、发生时间、报价状态。
2. 已收录最低报价、去年同期报价差额、可比样本数。
3. 历史趋势图及筛选器。
4. 报价明细、赠品、满减、条件与来源。
5. 个人兴趣、购买意愿、目标价、购买记录和备注。

筛选支持时间范围、年份、活动和直播间。趋势图必须同时提供可排序表格；选中报价点时显示完整明细。只有一个有效样本时显示单点和“样本不足”，不输出涨跌趋势。

### 7.5 活动比较

- 活动按实例管理，例如“2025年618”，包含类型、年份和起止日期。
- 报价关联到具体活动；活动外日期只提示核对，不自动改日期。
- 同一活动同规格有多个报价时，默认取活动内最低公开报价，标记“活动内已收录最低”，并保留全部记录入口。
- 年份无记录时留空，不用其他活动替代。
- 活动未结束时标记“截至当前已收录”。

### 7.6 直播间比较

只比较同一规格、同一活动或明确日期范围内的记录。展示直播间、报价、时间、赠品、辅助优惠、报价条件和来源。默认按已收录最低报价排序，不输出笼统的主播排名。

### 7.7 品类查看

第一版展示品类下商品和各商品涨跌，不直接计算品类平均售价。不同年份上播商品组成不同，平均值容易失真。后续如做品类趋势，应使用两个时期均有报价的固定可比规格集合，并展示样本数和计算方法。

### 7.8 我的关注与购买记录

关注字段包括：是否关注、兴趣程度（未设置/一般/很感兴趣）、购买意愿（未决定/想买/等降价/暂不考虑）、目标价、备注。

购买记录包括购买日期、规格、数量、关联报价、报价快照、实际支付金额（可选）和备注。实际支付金额只属于个人记录，不改变公开报价曲线；关联报价更正后，购买时保存的快照不变。

### 7.9 目标价提示

当关注规格新增有效通用报价且报价低于或等于目标价时，生成一次站内提示。有效期未知或已过时，显示“记录达到目标价，需核实是否仍有效”。导入历史记录不发送可购买提示。同一关注项和同一报价不重复提醒。

### 7.10 导入与导出

- 提供 UTF-8 CSV 模板和字段说明。
- 导入前预览，逐行提示缺失规格、金额格式错误、日期错误和重复风险。
- 无法唯一匹配的商品规格必须人工确认。
- 成功导入的报价初始为待核实；失败行提供原因清单。
- 支持导出商品、规格、报价、关注和购买记录，包含状态、关联 ID 和日期。

## 8. 数据模型

| Product 商品 | ID、品牌、品类、名称、别名、状态 |

## 9. 价格评价规则

价格评价只说明报价历史，不自动决定用户是否应该购买。

设当前报价为 P，可比有效历史报价集合为 H：

- 已收录最低报价 L = min(H)。
- 去年同活动差额 = P − 去年同活动已收录最低报价。
- 变化率 = 差额 / 去年同活动已收录最低报价 × 100%。
- 没有同期记录时显示“暂无可比数据”。
- 评价当前报价时，只使用当前报价发生日期之前的历史报价，避免未来数据倒灌。

| 条件 | 标签 |
| --- | --- |
| P 低于历史最低 | 新的已收录最低报价 |
| P 等于历史最低 | 持平已收录最低报价 |
| 高于历史最低且不超过5% | 接近已收录最低报价 |
| 其他 | 高于已收录最低报价 |

历史可比样本少于3条时只展示价格、差额和样本不足，不输出明确标签。若赠品发生变化，标签下必须显示赠品差异。

## 10. 关键验收标准

| 场景 | 预期结果 |
| --- | --- |
| 报价399元、满减50元 | 主趋势为399元，满减独立展示 |
| 直播券后399元 | 记录399元并标记已含直播券，不重复扣减 |
| 定金40元、尾款359元 | 总报价399元；只有定金不能成为有效报价 |
| 50ml和100ml同商品 | 不进入同一默认历史曲线 |
| 今年379元无赠品、去年399元送20ml | 展示下降20元，同时展示赠品差异 |
| 去年同活动无记录 | 显示暂无可比数据 |
| 活动内报价399/389/379元 | 活动比较值为379元，保留全部记录 |
| 只有两条历史记录 | 显示样本不足，不输出明确价格标签 |
| 目标价350元，新增有效报价349元 | 生成一次站内提示 |
| 导入两年前349元记录 | 纳入历史，不提示现在可以买 |
| 记录个人实际支付329元 | 不改变公开报价曲线 |
| 修改已购关联报价 | 趋势更新，购买快照不变 |
| 待核实记录为最低价 | 默认趋势和最低价不使用该记录 |
| 报价已过有效期 | 作为历史记录展示，不声称当前可购买 |

## 11. 非功能与质量要求

- 报价来源和附件可追溯；纠错保留修改日志。
- 默认归档而非直接删除，引用中的数据保持完整。
- 截图上传前提示遮挡无关个人信息。
- 本地部署优先；公网部署时补充登录、会话和附件访问控制。
- 以1万条报价作为第一版性能验证规模；常用搜索和筛选目标响应时间不超过2秒。
- 不使用红绿颜色作为唯一涨跌表达，金额变化同时显示文字和正负号。
- 区分无数据、无有效报价、筛选无结果和缺少同期数据四种空状态。

## 13. 关键指标

- 关注商品中具有跨活动可比记录的比例。
- 有效报价中具有可查证来源的比例。
- 新增报价平均操作耗时与纠错次数。
- 大促前使用历史比较设置目标价的次数。
- 查看比较后形成想买、等待或暂不考虑的比例。
- 购买后认为历史信息帮助决策的比例。

## 14. 开发前确认项

- 初始品类：优先选择自己最常关注的两个品类。
- 初始直播间：李佳琦及另外1至2个常看直播间。
- 历史来源：已有截图、官方页面和个人记录优先。
- 初始价格标签阈值：接近最低价暂按5%，界面注明统计范围。
- 站外提醒：暂不接入，先验证站内提醒价值。

**已确定的产品原则：直播间公开报价为主，满减为辅；同规格比较；赠品单独展示；价格评价与购买意愿分开；历史结论注明数据覆盖范围。**
