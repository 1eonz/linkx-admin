# linkx-admin Vue 3 重构 PRD

> 版本：v1.0  
> 日期：2026-09-21  
> 目标：在保持现有业务能力和后端兼容性的前提下，将 Vue 2 管理端重构升级为 Vue 3 管理端。

## 1. 背景

现有系统承载警务协同后台管理能力，包含登录认证、权限中心、基础数据、协同岗、排班、位置、警信扩展、预警、三方对接和多节点管理等业务。当前系统基于 Vue 2.6、Vuex 3、Vue Router 3、Element UI 和 Vue CLI 3，存在以下问题：

- 技术栈老旧，升级和维护成本高。
- 权限、License、全局开关和数据权限逻辑分散。
- 菜单存在主权限链路和 OAuth 试运行链路两套来源。
- 页面、共享组件和 API 返回协议不一致。
- storage、全局原型、事件总线和组件 ref 调用造成隐式耦合。
- 测试覆盖不足，难以支撑持续重构。

## 2. 产品目标

### 2.1 业务目标

1. 保持现有已上线业务模块可用。
2. 登录、登出、密码修改、心跳、超时退出和 License 提示行为保持一致或更清晰。
3. 菜单、按钮、License、全局开关和数据权限判定可解释、可测试。
4. 页面具有统一的查询、表格、分页、表单、弹窗、树选择、上传和错误处理体验。
5. 为未来新增业务域提供统一的页面和 API 开发模板。

### 2.2 技术目标

1. 完成 Vue 3、Vue Router 4、Pinia、Element Plus、Vite 升级。
2. 建立 TypeScript 类型边界，优先覆盖认证、权限、菜单、API 和共享组件。
3. 统一 API 响应、错误码、分页、上传和文件下载协议。
4. 消除 Vue 2 专属能力：`$set`、`$delete`、`$listeners`、`.sync`、全局 eventBus、原型覆写。
5. 实现按路由和业务域拆分的可观测、可测试架构。

## 3. 用户角色

| 角色 | 主要任务 |
| --- | --- |
| 超级管理员 | 配置系统全局参数、权限、角色、用户、License 相关能力 |
| 系统管理员 | 维护基础数据、组织、人员、业务配置 |
| 业务管理员 | 维护协同岗、排班、预警、应用和第三方业务 |
| 运维人员 | 维护节点、服务、客户端、数据授权和接口配置 |
| 普通后台用户 | 在数据权限范围内执行查询和被授权的业务操作 |
| 审计/只读用户 | 查看数据和记录，不执行写操作 |

> 实际角色名称和后端返回为准，前端不应写死角色权限，而应消费后端权限契约。

## 4. 功能范围

### 4.1 P0：基础可用能力

#### 登录认证

- 用户名密码登录。
- 设备 ID 生成和传递。
- 登录成功后保存 token、用户信息和基础权限上下文。
- 登录失败错误提示。
- 首次登录、密码过期、重置密码后的强制改密。
- 简单密码/复杂密码策略。
- 许可证告警和到期提示。
- keepalive 心跳。
- 无操作超时自动登出。
- HTTP 401 自动清理会话并返回登录页。
- 保留 redirect 地址。

#### 权限和菜单

- 获取用户菜单。
- 获取菜单权限、按钮权限、数据权限。
- 动态构建可访问路由。
- 侧边栏菜单与路由一致。
- 按钮权限控制创建、编辑、删除、授权、导出等动作。
- License 和全局开关过滤菜单。
- 无权限页面和 404 页面。

#### 后台壳层

- 左侧导航展开/收起。
- 移动端响应式布局。
- 面包屑。
- 用户菜单。
- 修改密码。
- 绑定警员。
- 退出登录。
- 页面加载和路由切换状态。
- 国际化切换。

### 4.2 P1：现有业务迁移

- 基础数据：全局配置、地图配置、布局配置。
- 权限中心：角色、人员、用户、前台/后台权限和自定义组织。
- 协同岗管理：协同岗、标签、层级、功能、关联人员和上下岗记录。
- 位置管理。
- 排班管理。
- 警信扩展：虚拟用户、归档群组。
- 预警管理。
- 三方对接：应用、南向、警单、通信、AI 智能体。

### 4.3 P2：可选/延后模块

- 多节点管理恢复为正式菜单。
- OAuth 菜单作为唯一菜单源。
- 已注释或已移除的历史模块恢复。
- Dashboard 业务看板增强。
- 操作审计和前端行为埋点。

## 5. 非功能需求

### 5.1 兼容性

- 支持当前生产环境认可的 Chromium 内核浏览器。
- 保持 `/linkx/admin/` 部署路径可用。
- 保持现有后端 API 前缀和认证头兼容。
- 支持中文，保留英文扩展能力。

### 5.2 性能

- 首屏路由壳层可独立加载。
- 业务页面按路由懒加载。
- 不把所有业务组件打入初始 chunk。
- 表格和树在大数据量下使用分页、懒加载或虚拟滚动。
- 页面切换不因全局 loading 造成不必要阻塞。

### 5.3 可访问性和可用性

- 表单控件有明确 label 和错误提示。
- 键盘可完成登录、查询、弹窗确认和主要操作。
- 所有危险操作有确认或可恢复提示。
- loading、empty、error 状态完整。
- 不依赖颜色作为唯一状态信号。

### 5.4 可测试性

- 认证、权限、菜单过滤、License 过滤和响应适配达到单元测试覆盖。
- 公共组件具备组件测试。
- P0/P1 核心流程具备 Playwright 冒烟测试。
- 发布前执行 lint、类型检查、单测、构建和核心流程回归。

## 6. 核心用户流程

### 6.1 登录

```text
访问系统
  -> 读取本地会话
  -> 无 token：进入登录页
  -> 输入用户名/密码
  -> 调用登录接口
  -> 成功：保存会话上下文
  -> 拉取全局配置、License、菜单和权限
  -> 建立动态路由
  -> 跳转 redirect 或首页
```

### 6.2 访问受限页面

```text
点击菜单
  -> router guard 判断 route permission
  -> 通过：加载页面
  -> 不通过：跳转 403/无权限页
  -> 页面动作再次判断 action permission
  -> API 由后端做最终权限校验
```

### 6.3 典型 CRUD

```text
进入列表页
  -> 初始化查询条件
  -> 请求列表
  -> loading / empty / error
  -> 查询、重置、分页
  -> 新增/编辑弹窗
  -> 表单校验
  -> 保存
  -> 成功提示并刷新列表
  -> 删除/批量删除需确认
```

## 7. 验收标准

### 7.1 P0 验收

- 未登录访问业务页会进入登录页并保留 redirect。
- 登录成功后刷新页面仍保持会话。
- 401 会关闭业务弹窗、清除会话并回到登录页。
- 菜单不可见时路由不可访问。
- 按钮权限不可用时对应操作不显示或不可执行。
- License 和全局开关关闭时对应模块不可见。
- 登录、登出、改密、心跳、超时退出流程有自动化测试。
- `/linkx/admin/` 生产部署路径可正常刷新和访问。

### 7.2 P1 验收

- 每个现有 P1 业务域至少有列表、查询、表单、删除/授权等原有能力。
- 页面数据与旧系统关键接口结果一致。
- 树选择、跨页选择、上传下载、导出和批量操作不回退。
- 关键页面在常用桌面分辨率和移动窄屏下无布局崩坏。

### 7.3 质量门禁

```text
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:e2e
pnpm build
```

## 8. 迁移策略

采用“新壳层先行、业务域渐进迁移、旧系统可回退”的策略：

1. 建立 Vue 3 项目骨架和 API/权限兼容层。
2. 迁移登录、Layout、路由、权限和通用组件。
3. 迁移全局配置和地图配置作为低风险业务试点。
4. 迁移权限中心和协同岗管理。
5. 迁移三方对接和多节点管理。
6. 开启新旧系统并行验收。
7. 移除 Vue 2、Vuex、Element UI 和旧构建链路。

每个业务域迁移完成后必须具备：

- 页面清单。
- API 清单和响应类型。
- 权限清单。
- 迁移前后截图/流程对比。
- 单元测试和冒烟测试。
- 回滚开关或旧入口。

## 9. 不在本期范围

- 后端权限模型重写。
- 后端接口 REST 化或服务拆分。
- License 业务规则重新定义。
- 大规模视觉重设计。
- 删除尚未确认的历史业务能力。
